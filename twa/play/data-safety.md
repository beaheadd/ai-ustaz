# Анкета «Безопасность данных» (Data safety) — готовые ответы

> Play Console → AI Ustaz → **Политика → Содержание приложения → Безопасность данных**.
> Основание — CLAUDE.md «Данные и приватность» и политика `https://aiustaz.pro/aiustaz/privacy.html`.
> Сверено с кодом 19.11.2026: аккаунтов нет; прогресс — localStorage на устройстве; аудио уходит на свой сервер
> только по «Проверить» (`app/src/speech/check.ts` → `/api/speech/`, сервис `speech/`), удаляется сразу после
> разбора; геолокация — только на устройстве (`CityPicker.tsx`); рекламы, аналитики и SDK третьих лиц нет.
> Если что-то из этого изменится (аккаунты, отправка записи устазу, аналитика) — анкету пересмотреть ДО выпуска.
> **Пересмотрено 20.11.2026 — уведомления о времени намаза** (владелец: «правильные, красивые уведомления время намаза
> приходило к клиенту»): по желанию на свой сервер уходят подписка push (адрес и ключи браузера), язык, название города
> строкой и расписание на 30 дней (`app/src/notify/`, `server/`). Координаты не уходят. Отметить два типа ниже.

## Шаг 1. Сбор и передача данных
| Вопрос | Ответ |
|---|---|
| Собирает ли приложение или передаёт третьим лицам какие-либо из обязательных типов данных? | **Да** (аудио — по нажатию «Проверить»; подписка на уведомления и город — если человек включил уведомления о времени намаза) |
| Все ли данные пользователей шифруются при передаче? | **Да** (только HTTPS, aiustaz.pro) |
| Можно ли удалить данные? | **Да** — способ: «Аккаунтов нет. Записи голоса удаляются с сервера сразу после проверки. Уведомления: «Ещё → Уведомления о намазе» → выключить — подписка, город и расписание удаляются с сервера сразу. Прогресс хранится только на устройстве: удалите данные сайта aiustaz.pro в настройках Chrome или удалите приложение. Запросы — [контакт]». Отдельной ссылки на удаление аккаунта не нужно — аккаунтов нет. |

## Шаг 2. Типы данных
Отметить **только**:

### Аудио → «Голосовые или звуковые записи» (Voice or sound recordings)
| Вопрос | Ответ |
|---|---|
| Собирается? | **Да** |
| Передаётся третьим лицам? | **Нет** (распознавание — на нашем сервере в Казахстане, во внешние API не уходит) |
| Обрабатывается эфемерно? | **Да** — запись хранится только в памяти на время разбора и сразу удаляется |
| Обязательно или по желанию? | **По желанию** — запись и «Проверить» только по нажатию; без проверки уроки работают |
| Цели | **Функциональность приложения** (проверка чтения) — и больше ничего: не аналитика, не реклама, не персонализация |

### Местоположение → «Приблизительное местоположение» (Approximate location) — с 20.11.2026, уведомления
| Вопрос | Ответ |
|---|---|
| Собирается? | **Да** — только **название города** строкой (выбранного в приложении) и расписание времён намаза этого города, если включены уведомления. Координаты (и своя точка по геолокации) на сервер НЕ уходят |
| Передаётся третьим лицам? | **Нет** |
| Обрабатывается эфемерно? | **Нет** — хранится, пока уведомления включены (расписание на 30 дней; обновляется при открытии приложения) |
| Обязательно или по желанию? | **По желанию** — уведомления выключены по умолчанию |
| Цели | **Функциональность приложения** (уведомление в начале времени намаза) |

### Идентификаторы → «Идентификаторы устройства или другие идентификаторы» (Device or other IDs) — с 20.11.2026
| Вопрос | Ответ |
|---|---|
| Собирается? | **Да** — подписка Web Push браузера (адрес push-сервиса и ключи шифрования), если включены уведомления. Рекламного ID нет |
| Передаётся третьим лицам? | **Нет** — сообщение уходит только через push-сервис самого браузера (Google FCM для Chrome), зашифрованным: это доставка, а не передача данных |
| Обрабатывается эфемерно? | **Нет** — хранится, пока уведомления включены; выключили — удаляется сразу; подписка, которую push-сервис отверг (404/410), удаляется автоматически; расписание, кончившееся больше 30 дней назад, — тоже |
| Обязательно или по желанию? | **По желанию** |
| Цели | **Функциональность приложения** |

### Всё остальное — НЕ отмечать
| Тип | Почему не отмечаем |
|---|---|
| Точное местоположение | координаты используются только на устройстве, чтобы найти ближайший город; на сервер не отправляются (Google: данные, которые не покидают устройство, — не «сбор»). Приблизительное (город) — см. выше, только для уведомлений |
| Личная информация (имя, почта, телефон, ID) | не спрашиваем: регистрации нет |
| Действия в приложении, прогресс уроков | хранятся только на устройстве |
| Рекламный ID | не используем; в APK нет `AD_ID` (проверка — `twa/README.md`, шаг 4) |
| Диагностика, журналы сбоев | SDK сбора сбоев нет |
| Фото, файлы, контакты, сообщения, финансы, здоровье, календарь | не используем |

Технический журнал веб-сервера (IP-адрес, время, адрес страницы) ведёт nginx для защиты и поиска сбоев; он не
связывается с пользователем, не используется для определения местоположения, аналитики или рекламы и описан в
политике (п. 7). В анкете его отдельным типом данных не отмечаем. Держать журнал коротким и вписать срок в политику
вместо `[срок]`. Если журнал начнут использовать для чего-то ещё — анкету пересмотреть.
