# 08. «Спросить AI Ustaz» — вопросы и ответы только из своей базы

**Запрос владельца (20.11.2026):** «поставить AI Ustaz … значок посередине нижнего меню … люди могут задавать свои
вопросы и получать ответы. Мы загрузим базу знаний, хадисы, Коран, тафсиры … например, по закяту … Только с нашей базы
данных, в интернете не будет искать, только с нашей базы данных, чтобы достоверная информация была. Сделай эту функцию,
но не выкатывай.»

**Состояние:** сервер сделан и проверен тестами, **не выкачен** (ни batr-world, ни nginx, ни workflow не трогали).
Приложение (значок посередине нижнего меню, экран вопроса) пишется параллельно под контракт ниже. Код — `server/ask.py`,
`server/kb.py`, `server/kb_load.py`, миграция `server/migrations/004_kb.sql`; формат базы — `docs/база-знаний.md`.

## 1. Что получает человек

Пишет вопрос (3–500 символов) на ru, kk или uz. Получает один из четырёх ответов:

| Вид | Когда | Текст | Источники |
|---|---|---|---|
| `ответ` | в базе нашлись подходящие записи | шаблон «Вот что есть в нашей базе по вашему вопросу…» (режим «поиск») или короткий пересказ ИИ, прошедший валидатор (режим «ии») | до 5 записей базы целиком: заголовок, текст, ссылка, издание; у хадиса — арабский, степень и кто её дал; у Корана — только ссылка «сура:аят» и перевод смыслов (аят приложение показывает из Tanzil) |
| `к-имаму` | личный вопрос фикха: «мой намаз действителен?», «можно ли мне…», «я должен заплатить закят с моей машины?», развод/талак, наследство, «харам ли…» | «Это личный вопрос … AI Ustaz не выносит фетв. Задайте его имаму вашей мечети, в ДУМК (muftyat.kz) или Imam AI.» + если нашлось: «Ниже — общие сведения из нашей базы. Это не ответ на ваш случай.» | общие записи базы (если есть) |
| `вне-темы` | политика, течения и секты, экстремизм, споры мазхабов и акыды, не-исламские темы; «тафсир аята N», если тафсира этого аята в базе нет | вежливый отказ; для тафсира — «В AI Ustaz нет ИИ-тафсира…» | нет |
| `нет-в-базе` | ничего не нашлось выше порога | «В нашей базе пока нет ответа на этот вопрос. Мы отметили, что такой ответ нужен (сам текст вопроса не сохраняем)…» | нет |

Тафсир аята, если он есть в базе (вид `тафсир`, та же «сура:аят»), показывается **как есть** с пометкой «без пересказа
ИИ» — вид `ответ`, режим `поиск`.

Поле `черновик: true`, если среди источников есть запись, которую устаз ещё не утвердил; в режиме «поиск» к тексту
добавляется «Материалы с пометкой «черновик» ещё проверяет устаз». Приложение показывает плашку «черновик» у ответа
и у каждого такого источника (правило 11).

Тексты шаблонов kk и uz — черновик для редактора-носителя (CLAUDE.md). uz-шаблоны отсылают к имаму мечети и ДУМК /
Imam AI, как велит CLAUDE.md, — для Узбекистана, возможно, нужен УМУз (вопрос 6 ниже).

Шаблон «нет в базе» изменён против задания («Мы записали тему» → «Мы отметили, что такой ответ нужен (сам текст вопроса
не сохраняем)»): тему мы не записываем — храним только число «не нашли» за день, иначе обещание было бы неправдой.

## 2. Контракт API

```
POST /api/ask/v1   {q: string (после обрезки 3…500 символов), lang: 'ru'|'kk'|'uz'}
  200 {вид: 'ответ'|'нет-в-базе'|'к-имаму'|'вне-темы', режим: 'поиск'|'ии', текст,
       источники: [{id, вид: 'коран'|'хадис'|'тафсир'|'статья'|'справка', заголовок, ссылка|null, текст, арабский|null,
                   источник, степень|null, кто_оценил|null, черновик, версия}],
       черновик}
  400 {ошибка:'question'} — пусто, короче 3, длиннее 500, не строка, тело не JSON-объект
  400 {ошибка:'lang'}     — не ru/kk/uz
  413 {ошибка:'size'}     — тело больше 8 КБ
  429 {ошибка:'rate'}     — больше 10 вопросов в минуту или 100 в сутки (по Алматы) с одного IP (ключ — хэш IP, в БД)
  403 {ошибка:'origin'}   — заголовок Origin есть, но не aiustaz.pro / www.aiustaz.pro (MUGALIM_ASK_ORIGINS)
  503 {ошибка:'kb'}       — база пуста или недоступна
GET /api/ask/health → {ок: true, записей: <в выдаче>, режим: 'поиск'|'ии'}
```

Отличия от задания: нет. Уточнения: `413` — с кодом `size` (как у `/api/push/`); тело не JSON → `400 question`
(отдельного кода в контракте не было); `версия` — строка «версия.8 знаков sha256».
Все ответы — `Cache-Control: no-store`; присланный вопрос в ответ не возвращается.

## 3. Как устроено

```
вопрос ──▶ классификатор (ask.классифицировать: словари фраз ru/kk/uz, детерминированно, чистые функции)
             ├─ вне-темы ─────────────▶ шаблон отказа
             ├─ тафсир «сура:аят» ────▶ запись вида «тафсир» из базы как есть │ иначе отказ «ИИ-тафсира нет»
             ├─ к-имаму ──────────────▶ шаблон «к имаму / ДУМК / Imam AI» + общие записи (если нашлись)
             └─ поиск PostgreSQL (tsvector; заголовок — вес A) ── ниже порога ──▶ нет-в-базе (+1 к счётчику дня)
                    │
                    ├─ режим «поиск» (по умолчанию) ──▶ шаблон + до 5 записей
                    └─ режим «ии» (MUGALIM_ASK_LLM=1 и ключ) ──▶ обезличить ─▶ Claude (JSON по схеме) ─▶ валидатор
                                                                   └─ ошибка / отказ / 10 с / не прошёл ─▶ режим «поиск»
```

- **Поиск** — полнотекстовый PostgreSQL, без новых сервисов и внешних эмбеддингов. `kb_texts.tsv` — словарь `russian`
  для ru, `simple` для kk/uz; `tsv_simple` — `simple` для всех: стеммер `russian` режет заимствования непоследовательно
  («закят» → «зак», «закята» → «закят»), поэтому основа слова ищется ещё и префиксом («закят:*» находит «закята»,
  «закятом», но не «закат»). Текст выдачи — на языке вопроса, если его нет — ru. Порог релевантности — доля значимых
  слов вопроса, найденных в записи (`MUGALIM_ASK_MIN_SHARE` = 0,3), цифры не ищем («1000000 тенге» — по «тенге»).
- **Классификатор** — словари в коде (`ВНЕ_ТЕМЫ`, `ТАФСИР`, `К_ИМАМУ`, `ЛИЧНОЕ` + `ФИКХ`, `НЕ_ТЕМА`); все три языка
  применяются всегда (по-русски в kk-интерфейсе — тоже). «Я/мне/мой/менің/mening…» + тема фикха → личный вопрос;
  вводные «хочу узнать», «скажите мне», «меня зовут» не делают вопрос личным. Это черновик: словари проверяет устаз,
  при сомнении — «к имаму» (безопаснее).
- **Режим «ии»** — только по флагу, ключ — только из `/etc/mugalim.env`. В модель уходит **только** обезличенный вопрос
  (`ask.обезличить`: e-mail, ссылки, @ники, телефоны/ИИН/номера карт — 9+ цифр; имя после «меня зовут», «менің атым»,
  «Мен …мын», «mening ismim») и найденные записи (id, вид, заголовок, ссылка, текст на языке вопроса; **без арабского**).
  Если после обезличивания осталось меньше двух слов — ИИ не зовём. Никаких IP, истории, идентификаторов. Модель
  `claude-opus-5-5` (`MUGALIM_ASK_MODEL`), `effort: low`, ответ — JSON по схеме `{вид: 'ответ'|'нет-в-базе', текст,
  источники: [id]}` (`additionalProperties: false`), серверный запасной вариант при отказе (`fallbacks: 'default'`),
  проверка `stop_reason == 'refusal'`, таймаут 10 с без повторов. Системный промпт — константа (`СИСТЕМНЫЙ_ПРОМПТ`):
  только по записям, ≤ 120 слов, на языке вопроса, без дословных аятов и хадисов, без фетв, без арабского письма.
- **Валидатор** (`ask.проверить_ответ_ии`, правило 4): JSON строго по схеме; все id — из найденных; у «ответа» хотя бы
  один id; нет арабского письма (U+0600–06FF, 0750–077F, 08A0–08FF, FB50–FDFF, FE70–FEFF — правило 1); нет фраз-фетв
  (ru/kk/uz: «недействител», «вы обязаны», «вам харам», «ваш брак», «жарамсыз», «haqiqiy emas»…); цитаты в «…», "…",
  “…” длиннее 20 символов дословно есть в тексте приложенной записи (иначе — выдуманная цитата, правило 2); ≤ 1200
  символов. Не прошёл — режим «поиск», в журнал — только код причины (`arabic`, `fatwa`, `quote`, `llm_timeout`…).

## 4. Границы (CLAUDE.md)

| Правило | Как соблюдено |
|---|---|
| 1. Коран — только дословно из Tanzil, арабский от ИИ блокируется | у записи `коран` арабского в базе нет (CHECK в БД и отказ загрузчика); арабское письмо в текстах базы — отказ; ИИ не получает арабского и не может его вернуть (валидатор) |
| 2. Хадисы — только из проверенной базы со сборником, номером, степенью и кто её дал | загрузчик и CHECK в БД не пускают хадис без них; ИИ хадисы не цитирует, выдуманные цитаты ловит валидатор; арабский хадиса — дословно из базы, ИИ его не видит |
| 4. Объяснения — только из утверждённой базы; LLM — только перефразирует, за флагом и через валидатор | режим «ии» выключен по умолчанию; ответ ИИ показывается, только если прошёл валидатор |
| 5. Без фетв, без ИИ-тафсира, без политики и сект | классификатор: «к имаму / ДУМК / Imam AI», отказ на тафсир (кроме изданного тафсира из базы как есть) и на политику/течения/споры мазхабов; фразы-фетвы в ответе ИИ — откат |
| 11. Новый религиозный контент проверяет устаз; плашка «черновик»; версия и хэш | статус записи, `черновик` в ответе, `MUGALIM_ASK_DRAFTS`; sha256 и версия при загрузке; публикация без подъёма версии — отказ |
| Данные и приватность | текст вопроса не храним нигде (ни в БД, ни в журнале); журнал `ask_log` — дата, вид, режим, код причины, число источников (90 дней); `ask_misses` — число «не нашли» за день; лимиты — по хэшу IP; в ИИ — только обезличенный текст |
| Бесплатно, без рекламы | ни платы, ни трекинга; SDK `anthropic` подключается только в режиме «ии» |

## 5. Что нужно от владельца

1. **Решение про внешний ИИ.** Сейчас CLAUDE.md разрешает в LLM «только обезличенный структурированный текст: номер
   аята, слово, код правила». Вопрос свободным текстом — даже обезличенный — **это расширяет**: человек может написать
   о себе то, что обезличивание не уберёт, и текст уйдёт на серверы Anthropic за пределами РК. Нужно явное решение
   владельца (и строка в CLAUDE.md и политике конфиденциальности), иначе режим «ии» не включать. Без него функция
   полностью работает в режиме «поиск».
2. **Ключ API** (если «да» в п. 1): `ANTHROPIC_API_KEY=…` в `/etc/mugalim.env` (600), `MUGALIM_ASK_LLM=1`, перезапуск
   `mugalim-api`. В git и в чат ключ не класть. Сеть сервера — выход к `api.anthropic.com`.
3. **Кто наполняет базу** (закят, намаз, пост, хадисы, тафсир) и **кто проверяет** (устаз из братьев сейчас; совет
   и ДУМК — когда вырастем). Формат и порядок — `docs/база-знаний.md`.
4. **Источники и лицензии:** материалы ДУМК (muftyat.kz) — нужно разрешение ДУМК на перепубликацию (как с временем
   намаза — письмо); сборник хадисов с переводом и оценками — какое издание и на каких условиях; тафсир — какое изданное
   издание и разрешение правообладателя; переводы смыслов Корана — какие и с чьего разрешения.
5. **Выкатка** — когда скажете: nginx `location /api/ask/` на aiustaz.pro (строки — `server/README.md`), копия
   `server/` в batr-world, загрузка `content/kb/spravka.jsonl` на сервере. Сейчас не выкачено.
6. **Узбекский:** uz-шаблоны отсылают к ДУМК / Imam AI (как в CLAUDE.md); для пользователей из Узбекистана, возможно,
   правильнее «Управление мусульман Узбекистана (muslim.uz)» — решить. В стартовой справке uz-текстов нет (по заданию
   ru и kk): uz-вопросы получают ru-текст, а поиск по uz-словам находит только записи с uz-текстом.
7. **Словари классификатора и шаблоны** — проверить устазу (особенно что считать личным вопросом фикха).

## 6. Как включать (на сервере, когда решите выкатывать)

```bash
cd /opt/mugalim/server
python -m kb_load --check ../content/kb/spravka.jsonl && python -m kb_load ../content/kb/spravka.jsonl
curl -s http://127.0.0.1:8031/api/ask/health       # {"ок":true,"записей":11,"режим":"поиск"}
# режим «ии» — только по решению п. 1: в /etc/mugalim.env MUGALIM_ASK_LLM=1 и ANTHROPIC_API_KEY=…, затем
systemctl restart mugalim-api                       # health → "режим":"ии"
# черновики скрыть (когда база утверждена): MUGALIM_ASK_DRAFTS=0
```
