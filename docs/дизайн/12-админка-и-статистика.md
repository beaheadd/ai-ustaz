## Где что

## Вход и роли

- Почта → 6-значный код письмом. Письмо уходит через локальный Postfix по SMTP 127.0.0.1:25, отправитель no-reply@aiustaz.pro.
  - Не sendmail: служба `mugalim-api` работает с NoNewPrivileges.
  - Код хранится только как HMAC с секретом `MUGALIM_ADMIN_SECRET` (его создаёт setup-server.sh).
  - Код живёт 10 минут, на него 5 попыток.
  - Лимиты: 3 кода на почту и 10 на IP за 15 минут.
  - Ответ на «прислать код» одинаков для любой почты: не раскрывает, кто админ.
- Сеанс:
  - cookie `aiustaz_admin` (HttpOnly, Secure, SameSite=Strict, Path=/api/admin);
  - в базе хранится sha256 токена;
  - живёт 30 дней, без активности заканчивается через 7 дней;
  - изменения принимаются только с заголовком `X-Aiustaz-Admin: 1` и своим Origin.
- Роли:
  - **владелец** — всё, включая админов;
  - **админ** — содержимое и статистика;
  - **просмотр** — только смотрит.
- Первый владелец берётся из `MUGALIM_ADMIN_OWNER_EMAILS` в `/etc/mugalim.env`. Почта не хранится в git.
  - Ставит её workflow batr-world «AI Ustaz admin: set owner» из секрета GitHub `AIUSTAZ_ADMIN_OWNER_EMAIL`.
  - Такого владельца из админки не удалить и не понизить.
- Журнал (`admin_audit`) записывает каждое действие: вход, выход, админы, чтецы, хадисы. Кто, что, когда, над чем.

## Статистика: что считаем и чего нет

CLAUDE.md: без рекламы, рекламного трекинга и сторонней аналитики; данные не продаём и не передаём; база в РК.

**Отправляется** — только с aiustaz.pro, только на свой сервер, без cookie, `POST /api/stats/e`:
- случайный анонимный id устройства (`localStorage aiustaz:sid.v1`) и id сеанса (новый после 30 минут тишины);
- язык;
- класс устройства: телефон, планшет или компьютер, плюс семейство ОС;
- открыто ли как установленное приложение;
- домен, откуда пришли — только в начале сеанса;
- путь экрана латиницей (`quran/sura`) и номер: сура, хадис, урок;
- пульс раз в 30 секунд, пока страница видна. Из пульса считается время.

**Не отправляется и не хранится:**
- имя, телефон, почта;
- IP — только хэш на минуту для лимита;
- строка браузера (User-Agent);
- город и координаты;
- текст поиска;
- записи голоса.

**Не считаем вовсе:**
- batr.kz и тестовые адреса;
- «Не отслеживать» и Global Privacy Control;
- тех, кто выключил статистику: «Ещё» → «Анонимная статистика».

Сырые события хранятся 90 дней. Дальше остаются только суточные итоги (`stats_daily`), их подводит `mugalim-jobs` раз в час.

**Первая страница админки:**
- кто зашёл сегодня, за 7 и за 30 дней, сколько из них новых;
- сеансы; время за сеанс (среднее и медиана); время в день на человека;
- сколько установили приложение; сколько подписок на уведомления;
- график «посетители по дням» с подсказкой при наведении и таблица по дням;
- какие страницы смотрели: просмотры, люди, время;
- самые частые суры, хадисы и уроки;
- языки, устройства, системы, откуда пришли;
- возвращаются ли: на следующий день и в течение недели;
- когда заходят — по часам Алматы.

Графики — по методу dataviz: одна серия, один цвет, числа текстом рядом, светлая и тёмная тема.

## Содержимое

- **Коран** — только чтение (правило 1).
  - 114 сур из проверенной копии Tanzil с теми же проверками sha256, что в приложении. Используются те же модули `app/src/quran/loader.ts`, `mushaf.ts` и `tajweed.ts`.
  - Цвета таджвида и легенда из 11 правил.
  - «▶» у каждого аята и «Слушать суру» выбранным чтецом. Запись берётся со своего зеркала `/aiustaz-audio/…`, если издание скачано целиком, иначе с CDN AlQuran Cloud.
- **Чтецы** — все из `content/audio-sources.json`. По каждому видно:
  - разрешение и условия;
  - скачан ли на наш сервер (`/aiustaz-audio/editions.json`).

  Для каждого чтеца есть переключатели «Включён в приложении» и «По умолчанию». Чтеца без разрешения включить нельзя (правило 3).
- **Хадисы** (правило 2) — только отметки к записям проверенной базы HadeethEnc; текст здесь не пишут и не правят.
  - «Скрыть» — хадис пропадает в приложении из разделов, поиска и с экрана хадиса.
  - «Проверено устазом (имя)» — снимает плашку «Черновик».
  - «Ждут устаза» (342 хадиса не в приложении) → «Добавить: проверено устазом». Такой хадис попадает в приложение следующей сборкой: «Выгрузить отметки устаза» → `content/hadith/одобрено.json` → `tools/hadith/build_hadith.py`.
- Каждая публикация настроек записывается с версией и sha256 (`content_versions`; правило 11).
- Приложение берёт настройки при запуске (`GET /api/content/config`, 5 минут кэша, ETag). Без сети действуют данные сборки и последний ответ.
- **Заготовки:** «Зикры и дуа», «Намаз», «Уведомления» (число подписок).

## Выкатка (batr-world)

1. Скопировать `server/` вместе с `server/admin_static/` в `aiustaz/server/`. Workflow «AI Ustaz server (push)» ставит его на сервер: секрет `MUGALIM_ADMIN_SECRET` создаётся сам.
2. nginx aiustaz.pro (`deploy/aiustaz-app.nginx.conf`):
   - `/admin/` — статика с CSP без inline;
   - `/api/admin/`, `/api/stats/e`, `/api/content/config` — прокси на 127.0.0.1:8031.

   На batr.kz ничего этого нет.
3. Владелец: секрет `AIUSTAZ_ADMIN_OWNER_EMAIL` в batr-world → workflow «AI Ustaz admin: set owner».
4. Письма с кодом доходят надёжнее, когда в DNS aiustaz.pro есть DKIM (`mail._domainkey`) и DMARC — те же записи, что для рассылки писем.
