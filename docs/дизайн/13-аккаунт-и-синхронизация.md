## Правила

- Вход **по желанию**: без него всё работает как раньше, всё — на устройстве. Только на aiustaz.pro (на batr.kz строки входа нет).
- Аккаунт — **только 16+** (CLAUDE.md, v1): без отметки «Мне 16 лет или больше» сервер не создаёт аккаунт (`400 age`).
- Согласие простыми словами на экране входа: что хранится, где (сервер AI Ustaz в Казахстане), как удалить. Версия текста — `account-1`.
- Паролей нет. Вход: **4-значный код из письма** (тот же механизм, что у админки) или **Google**.
- Без рекламы, трекинга и продажи данных; Google получает только то, что нужно для входа, и только после нажатия.

## Вход

- **Код:** 4 цифры, HMAC с секретом `MUGALIM_ADMIN_SECRET` в своей «области» (`account:` + почта — код аккаунта не подходит к админке), 10 минут, 5 попыток — потом сгорает, сравнение за постоянное время; не больше 5 кодов в час на почту и 20 в час с IP (хэш); проверка — 20 за 15 минут с IP. Письмо — «Код входа: 1234», SMTP 127.0.0.1:25 как у админки (отправка не менялась).
- **Google:** Google Identity Services. Скрипт `https://accounts.google.com/gsi/client` вставляется **только по нажатию** «Войти через Google» (`account/google.ts`); затем на месте нашей кнопки — кнопка Google (браузер не даёт открыть окно не из нажатия → два нажатия). Сервер проверяет ID token: подпись RS256 по открытым ключам Google (кэш в `account_jwks`, 6 часов; неизвестный `kid` — перекачать не чаще раза в 5 минут), `aud` = `MUGALIM_GOOGLE_CLIENT_ID`, `iss`, `exp`, `iat`, `email_verified`. Берём только `email` и `sub`; имя и фото не храним. Нет client ID — кнопки нет (`/api/account/config`).
- **Одна почта — один аккаунт:** Google и код на ту же почту ведут в один аккаунт (`google_sub` привязывается к почте).
- **Apple:** сервер готов за флагом (`MUGALIM_APPLE_SERVICES_ID`, `MUGALIM_APPLE_REDIRECT`; та же проверка по `https://appleid.apple.com/auth/keys`, `aud` = Services ID), кнопки в приложении нет — по решению владельца «пока без него».
- **CSP** (`scripts/after-export.mjs`): `script-src 'self' https://accounts.google.com/gsi/client`, `connect-src 'self' https://accounts.google.com/gsi/`, `frame-src https://accounts.google.com/gsi/`, `style-src … https://accounts.google.com/gsi/style` — и больше Google нигде (`check-dist` п. 8). Сборка одна для aiustaz.pro и batr.kz, поэтому адреса есть в политике обеих, но код на batr.kz вход не показывает и скрипт не грузит.

## Сеанс

- Cookie `aiustaz_account`: HttpOnly, Secure, SameSite=Lax, Path=/api/account; в базе — sha256 токена. 180 дней, без активности — 60.
- Изменения — только с заголовком `X-Aiustaz-Account: 1` и своим Origin.
- «Выйти» — этот сеанс; «Выйти на всех устройствах» — все. На устройстве данные остаются.

## Что синхронизируется (и ничего больше)

| Документ | Ключи устройства | Правило слияния |
|---|---|---|
| `progress` | `progress.v1`: уроки, дни занятий, «первый вход пройден», «ИИ-предупреждение показано» | уроки: пройден — «или», лучший и попыток — максимум, последний — позже; дни — объединение (≤ 400); флаги — «или»; сброс прогресса — новая «эпоха», более поздняя заменяет целиком |
| `dhikr` | `dhikr.v1`: счёт, цели, избранное | счёт — **по устройствам**: у каждого своя доля «сегодня» (день по Алматы) и «всего», на экране — сумма (≥ 0); нажатия на двух телефонах складываются, сброс — своя доля отрицательная; цель — последняя по времени; избранное — множество с «надгробиями» |
| `quran` | `quran-reading.v1`, `quran-bookmark.v1` | последнее по времени (закладка одна, как в мусхафе; убрали — `null`) |
| `settings` | язык (`progress.v1`), `theme.v1`, `prayer-place.v1` (только город из списка; своя точка по геолокации НЕ уходит и не заменяется), `prayer-asr.v1`, `quran-words.v1`, `quran-view.v1`, `quran-font.v1`, `quran-reciter.v1`, `notify.v1` (только выбор намазов и «напомнить заранее») | по полю, последнее по времени |
| `zakat` | `zakat.v1` | только с выключателем «Сохранять суммы закята в аккаунте» (выкл.); выключили — документ на сервере удаляется сразу |

**Не синхронизируется никогда:** история чата (`ask-history`), голос, фото, id статистики (`sid.v1`, `stats-off.v1`), подписка на уведомления и «включено/отправлено/до» в `notify.v1`, согласие на проверку голосом и пояснение о микрофоне (свои у устройства), кэши (`content-config`, `prayer-official`, `zakat-rates`, `zakat-prices`, `quran-audio-mirror`, `quran-player`), отметки показа (`install-banner`, `update-dismissed`, `prayer-invite`, `quran-reciter-asked`, `prayer-auto`, `dhikr-filter`), `прохождение` урока.

«Последнее по времени» — пара `[значение, мс]`. Значение с устройства, которого не было в общей версии (первая синхронизация), получает время 0: **аккаунт важнее того, что телефон выбрал до входа**; при равенстве — то, что на сервере.

## Как идёт синхронизация

- Сервер **не сливает**: хранит документ с версией и пишет только поверх той версии, что видел клиент (`PUT /api/account/sync {docs:{ключ:{base, data}}}` → записано или `conflicts` с текущей версией). Сливает приложение (`merge.ts`) и повторяет (до 3 раз).
- «База» — документ, с которым устройство последний раз сошлось с сервером (`aiustaz:account-sync.v1`; там же случайный id устройства для счёта зикров). Тот же аккаунт на том же устройстве продолжает с базы; другой аккаунт — новая база и новый id устройства.
- Когда: при входе; при запуске (если вошли; чанк `account` грузится только тогда); когда приложение снова на экране; когда вернулась сеть; через 4 с после записи синхронного ключа. Сначала всегда устройство: без сети всё работает, синхронизация догонит.
- После записи данных другого устройства модули перечитывают свой ключ (`приВнешнемИзменении` в progress, theme, dhikr, quran, prayer, notify, audio, wordHighlight, readingView, fontSize). Уведомления сами отправляют новое расписание, если выбор намазов изменился.

## Админка

- Если почта аккаунта — админ (`admin_users`, не отключён), `/api/account/me` отдаёт роль, «Ещё» показывает «Админ-панель».
- Нажатие → `POST /api/account/admin` → сервер открывает обычный сеанс админки (cookie `aiustaz_admin`, Path=/api/admin, SameSite=Strict, как при входе по коду) → переход на `/admin/` уже вошедшим. Журнал `admin_audit` — «вход через аккаунт приложения».
- Вход в аккаунт через Google тоже даёт админку, если почта Google — в списке админов (почта подтверждена Google).

## Удаление и мои данные

- «Удалить аккаунт» — пользователь, сеансы, документы и коды удаляются сразу (`ON DELETE CASCADE`); на устройстве всё остаётся.
- «Скачать мои данные» — JSON: почта, способы входа, документы с версиями, сеансы (класс устройства и время).
