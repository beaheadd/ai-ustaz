# 05. Коран: полный текст, чтение, плеер, запись и проверка (19.11.2026)

**Запрос владельца (19.11.2026):** «Коран полностью, все аяты … Коран нужно Мишари Ар-Рашид добавить аудио, добавить плеер нужно, чтобы можно было слушать, и когда экран выключен. Чтобы Коран мог читать и проверить, как он читает … заходишь и читаешь любой аят, и записываешь голос и проверяешь, где ошибки.»

**Что в этом документе.** Данные Корана уже готовы (раздел 1). Раздел 2 — контракт для трёх следующих агентов: плеер, запись и проверка, экраны. Хадисы, тафсир, переводы смыслов и права на аудио Алафаси ведёт **отдельный процесс**. Здесь их нет: ни перевода, ни тафсира, ни хадисов, ни аудиофайлов.

Жёсткие правила (CLAUDE.md), которые касаются этой работы:
- **правило 1** — Коран только дословно из копии Tanzil для показа;
- **правило 3** — только живые записи кари по договору, без синтеза;
- **правило 5** — без ИИ-тафсира;
- **правило 7** — только «Проверьте себя» и «Подсказка»;
- **правило 8** — неверный вариант аята не показывать;
- **правило 9** — без текста Корана в уведомлениях;
- **правило 11** — пояснения с плашкой «черновик»;
- **приватность голоса**;
- **QML** — проверка голосом только в сборке своего домена.

## 1. Что сделано (данные)

### 1.1. Копия Tanzil для показа
- **Файл.** `content/quran/quran-uthmani-marks.xml` — побайтная копия, загружена с tanzil.net 19.11.2026 (финал, по ревью).
  - Tanzil Uthmani v1.1, XML, 114 сур, 6236 аятов.
  - sha256 `af9311c521b5dadab01ea1ef259c281ffa83cf224bad24ee89469ce1c3c72916`.
  - Параметры загрузки: `quranType=uthmani, outType=xml, marks=true, sajdah=true, rub=true, alef=true, tatweel=true, stanween=true`
    (форма tanzil.net/download: знаки остановки, саджда ۩, руб‘ ۞, надстрочный алиф, **татвиль перед ним** — так по умолчанию
    на сайте, и **«Include sequential tanweens»** — малые мимы U+06ED/U+06E2 после танвина: начертание икляба, идгама и ихфы
    танвина, как в мусхафе Медины).
  - **Внешний якорь sha256** — `tools/quran/quran_common.py` `ЭТАЛОН_SHA256_ПОКАЗА` (с датой и параметрами). `check_quran`
    сверяет с ним и файл, и `sources.json`: подмена XML вместе с `sources.json` и производными не пройдёт.
  - Первая загрузка того же дня (`33f4113d…bf57`, без `tatweel` и `stanween`) — заменена: в ней не было ~6640 малых мимов
    после танвина и татвиля перед надстрочным алифом (ревью 19.11.2026, тренер таджвида без визуальной подсказки идгама/ихфы).
- **sources.json.** Запись `tanzil` — копия **для показа**, с путём, sha256, датой и параметрами загрузки. Отдельная запись `tanzil-phonetic` — копия без знаков из `quran-transcript` 0.6.4 (sha256 `dc4e68cb…3f07`): **только фонетика и выравнивание**, на экран не выводится. Блок копирайта Tanzil не тронут.
- **Где копирайт.** Блок условий Tanzil лежит в каждом производном файле (индексе и каждой суре). Ссылка на tanzil.net — в «Лицензиях».

### 1.2. Чем две копии отличаются (сверено по всем 6236 аятам)
- **Знаки — отдельными токенами через пробел.** Они есть только в копии для показа:

  | Знак | Сколько |
  |---|---|
  | ۖ | 1682 |
  | ۗ | 603 |
  | ۚ | 1972 |
  | ۛ | 12 |
  | ۙ | 68 |
  | ۘ | 22 |
  | ۜ | 5 |
  | ۞ | 199 (всегда в начале аята) |
  | ۩ | 15 (всегда в конце аята) |

  Ещё 2 раза ۜ стоит внутри слова (сакта по начертанию).
- **Слова.** Если убрать знаки-токены, слова обеих копий совпадают **по числу и порядку во всех аятах**. Поэтому номер слова (с 1, без знаков) одинаков в обеих копиях.
- **Начертание слов совпадает.** Если убрать знаки-токены, копия для показа **побайтно равна** фонетической во всех 6236
  аятах и бисмиллах (татвиль, малые мимы U+06ED — 4807, U+06E2 — 2445, включая те, что были и без `stanween`). Проверено
  скриптом при загрузке. Первая выгрузка (без `tatweel`, `stanween`) различалась на 4790 аятах — её больше нет.
- **В аль-Фатихе** отличий нет (татвиль в 1:1–1:4 на месте, как в фонетической копии).

### 1.3. Производные (статические файлы сборки)
- **Как собирается.** `python3 -I -B tools/quran/build_quran.py` (без сети, `--check` — только сверка) пишет:
  - `app/public/quran/NNN.<sha256[:20]>.json` — 114 сур. Поля:
    - `формат: 1`, `источник: 'tanzil-uthmani-1.1'`, `копия: 'показ'`, `файлИсточника`, `sha256Источника`;
    - `сура`, `имя` (арабское, атрибут XML), `аятов`;
    - `бисмилла` — атрибут XML или `null` (у сур 1 и 9);
    - `аяты: [{ аят, текст }]` — дословно;
    - `копирайт`.
  - `app/public/quran/index.<sha256[:20]>.json` — индекс. Запись суры: `{ сура, имя, аятов, файл, sha256, транслит: { ru, kk }, синонимы }`, плюс `статусТранслита: 'черновик'` и `копирайт`. `синонимы` — только для поиска (латиница «Al-Baqarah», привычные «Ясин», «Табарак»), на экран не выводятся; черновик (`ТРАНСЛИТ_LAT`, `СИНОНИМЫ` в `quran_common.py`).
  - `app/src/quran/manifest.generated.ts` — `МАНИФЕСТ_КОРАНА`: имя и sha256 индекса. **Текста Корана в JS нет.**
- **Как попадает в сборку.** Expo `export` копирует `app/public/` в корень `dist/` как есть. Адреса — `/aiustaz/quran/…` (baseUrl). Хэш в имени нужен `check-dist` (SW batr.kz кэширует файлы по адресу навсегда). `release-batr.sh` копирует `dist/` целиком — `quran/` уходит вместе со сборкой; `.gitignore` batr-world её не режет (проверено `git check-ignore`).
- **Транслитерация имён сур.** ru — черновик для устаза и редактора: «аль-Фатиха», «аль-Бакара»… Это транслитерация арабского имени, не перевод смыслов. **kk пока `null`** («если сомневаетесь — только номер и арабское имя»): экран показывает «N-сүре» и арабское имя. Транслитерации правятся в `tools/quran/quran_common.py` (`ТРАНСЛИТ_RU`), затем пересборка.

## 2. Контракт

### 2.1. Маршруты (сделано 19.11.2026 — §2.7; `app/src/engine/routes.ts`)

| Экран (`ИмяЭкрана`) | hash | Параметры | Вкладка | Меню |
|---|---|---|---|---|
| `коран` (есть) | `#/quran` | — | `коран` | видно (корень раздела) |
| `сура` (сделано) | `#/quran/sura?n=2&a=255` | `{ номер: number /*1…114*/; аят?: number /*1…аятов*/ }` | `коран` | **видно** (не в `ФОКУСНЫЕ`, без `низ`) |
| `проверкаАята` (сделано) | `#/quran/check?n=2&a=255&p=1` | `{ номер; аят; часть?: number }` | `коран` | видно; запись — встроенной `<ПанельЗаписи>`, без закреплённого низа |

- **`routes.ts`.** Сейчас путь — один сегмент, параметр — один сегмент после (`#/lesson/3`). Нужно:
  1. путь из двух сегментов: `ПУТИ.сура = 'quran/sura'`, `ПУТИ.проверкаАята = 'quran/check'`; сопоставлять самый длинный путь;
  2. параметры query-строкой после `?`: `n`, `a`, `p` — только цифры. `вХэш` пишет `a` и `p`, только если они заданы.

  `#/quran` без хвоста — по-прежнему `коран`. Неверные `n`/`a` дают `null` (как сейчас). Аят больше числа аятов суры проверяет экран после загрузки: начинает с 1 и пишет «нет такого аята».
- **Глубокая ссылка.** `#/quran/sura?n=2&a=255` должна давать стек `[главная, коран, сура]`: «назад» → список сур. Если это сложно, `[главная, сура]` (вкладка «Коран» из `ВКЛАДКА_ЭКРАНА`) тоже допустимо — решает агент экранов.
- **Список сур (`#/quran`)** заменяет нынешнюю аль-Фатиху. Каждая строка: номер, транслитерация (ru; для kk — «N-сүре»), арабское имя (`АрабскийТекст`), число аятов. Поиск по номеру и транслитерации — по желанию. «Как объясняет» и «Источник и условия Tanzil» остаются.
- **Без текста Корана:** в `document.title`, заголовке экрана, уведомлениях и Media Session. Заголовок — «Сура аль-Бакара (2)».

### 2.2. Данные (готово; `app/src/quran/`)

```ts
import { useИндексСур, useСура, загрузитьИндексСур, загрузитьСуру, сураИзКэша, индексИзКэша } from '../quran/data';
import { разборАята, словаАята, числоСлов, остановкиАята, частиПоОстановкам, ЗНАКИ, ОСТАНОВКИ_ДЛЯ_ЧАСТЕЙ } from '../quran/text';

useИндексСур()   → ({ состояние: 'загрузка' } | { состояние: 'нет'; нетСвязи: boolean; причина } | { состояние: 'есть'; данные: ИндексСур }) & { повторить() }
useСура(н | null) → то же с данными СураКорана; null — ничего не грузить
загрузитьСуру(н): Promise<{ ок: true; данные: СураКорана } | { ок: false; причина: 'нет-связи' | 'сбой-сервера' | 'нет-файла' | 'не-прошло-сверку' }>
сураИзКэша(н): СураКорана | null            // уже загруженное, без ожидания (плеер — следующая сура)

ИндексСур  { сур: 114; аятов: 6236; суры: ЗаписьСуры[]; статусТранслита; копирайт; источник; файлИсточника; sha256Источника }
ЗаписьСуры { сура; имя /*арабское*/; аятов; файл; sha256; транслит: { ru: string | null; kk: string | null } }
СураКорана { сура; имя; аятов; бисмилла: string | null; аяты: АятКорана[]; копирайт; источник; файлИсточника; sha256Источника }
АятКорана  { сура; аят; текст }               // текст — дословно, со знаками-токенами
```

- **Состояния экрана.**
  - `нетСвязи: true` (`нет-связи`, `сбой-сервера`) — «Нет связи» и «Повторить».
  - `false` (`нет-файла`, `не-прошло-сверку`) — «Текст не прошёл сверку — не показываем», и ни одного аята.

  Неудачи не кэшируются. Таймаут запроса — 20 с.
- **Как грузится.** Одна сура — один запрос: аль-Бакара ≈ 114 КБ, обычно 1–20 КБ. Цепочка сверки sha256: манифест → индекс → сура. На телефоне (натив) относительного адреса нет — TODO: адрес своего домена или файлы в пакете.
- **Бисмилла** (`сура.бисмилла`) рисуется перед аятом 1 **отдельной строкой, без номера**: это не аят. У суры 1 бисмилла — сам аят 1:1, у суры 9 её нет.
- **Номер аята** — отдельный элемент рядом с текстом (как в `АятСоСловами`). В строку Корана ничего не вставлять: ни ۝, ни цифры.
- **`text.ts`** (чистые функции, без импортов).
  - `разборАята(текст)` → токены `{ вид: 'слово', текст, номерСлова }` или `{ вид: 'знак', текст, знак, послеСлова }`. Склейка токенов через пробел равна строке. Знаки остаются в тексте и рисуются Amiri Quran — ничего не вырезать.
  - **Номер слова — по `разборАята`**, без знаков-токенов. В старом `АятСоСловами` номер — индекс `split(' ')`, вместе со знаками: для полного Корана брать `разборАята`.
  - `частиПоОстановкам(текст)` → `{ номер, словоС, слов, токенС, токенПо, знакВКонце }[]`. Где можно остановиться — ۘ ۗ ۖ ۚ (**черновик политики, утверждает устаз**). Не делим по ۙ (не останавливаться), ۛ (пара), ۜ (сакта), ۞, ۩.
  - **Статистика:** самый длинный аят — 2:282 (128 слов). Частей длиннее 20 слов — 209, длиннее 30 — 21. Самые длинные — 24:61 и 4:23, по 49 слов.
- **Длинные суры.** Аль-Бакара — 286 аятов: список — виртуализированный (`FlatList`/`windowSize`) или по страницам. Переход к `a` — прокрутка к аяту. Пока Amiri не загружен, текст прозрачен (как в `АятСоСловами`).

- **Поведение.**
  - Очередь — аяты одной суры `сАята…поАят`. После последнего — «стоп»: следующая сура сама не начинается.
  - Повтор аята ×N — тот же файл N раз. «По кругу» — после `поАят` снова `сАята`, до «Стоп». Это для заучивания, не награда.
  - Бисмилла — отдельным файлом источника перед 1-м аятом, не у сур 1 и 9. Пока `текущий.бисмилла` — подсвечивать строку бисмиллы, а не аят 1.
  - «Следующий» на последнем аяте без круга ничего не делает. «Предыдущий» на первом — тот же аят сначала. `кАяту` вне отрезка расширяет отрезок.
  - Пауза ОС (звонок, наушники) → «пауза». Браузер не дал играть без жеста → «пауза», не ошибка.
  - Нет связи или файла → «ошибка» и «Повторить» (`продолжить()`): тот же аят заново.
- **Что делают экраны** (App.tsx и экраны — зона агента экранов).
  - `<МиниПлеер />` — в `App.tsx` над `<НижнееМеню />`, обычным элементом колонки. В «стоп» он ничего не рисует. Совет: показывать и на фокусных экранах — иначе звук идёт без кнопки «стоп». Или звать `плеер.пауза()` при входе в урок.
  - Экран суры:
    - сверху `<КнопкаСлушать сура={н} />` — сама покажет `<СтрокаБезЗвука />`, если играть нельзя;
    - у аята — `<КнопкаСлушать вид="значок" сура={н} сАята={а} />` («слушать с этого аята»);
    - подсветка текущего аята — `useПлеер().текущий`.
  - Экран проверки аята:
    - «Сравнить с кари» — `плеер.играть({ сура, сАята: а, поАят: а, повторАята: 1 })`, кнопка — только при `доступныйИсточник()`;
    - перед записью и «Послушать себя» — `плеер.пауза()`: микрофон не должен слышать кари.
  - Язык подписей экрана блокировки — `установитьЯзыкПлеера(язык)`. `<МиниПлеер>` и `<КнопкаСлушать>` делают это сами.
- **Хранение.** `localStorage` `aiustaz:quran-player.v1` = `{ версия: 1, сура, аят, повторАята }`. Только на устройстве, в try/catch. Голоса и персональных данных нет. Повтор в хранилище — только выбор человека чипом ×N (разовые ×3/×5 у аята и ×1 «Сравнить с кари» его не меняют). После «стоп» обработчики Media Session снимаются (`setActionHandler(…, null)`, metadata = null, playbackState = 'none'); устаревшее событие `error` (src уже сменили) игнорируется.
- **Мини-плеер.** Сверху «Сура аль-Бакара · аят 255 (повтор 2 из 3)», ниже «Чтение: …» и состояние. Кнопки: ×1/×3/×5, ⏮, ▶/❚❚, ⏭, «по кругу», ✕. Цели нажатия 48–56 px. Без анимации, звуков, счётчиков. Проверено на 320 и 360 px, ru и kk, в светлой и тёмной теме.

#### 2.3.1. Как работает при выключенном экране (веб)
- **Один `<audio>`.** `new Audio()` — синглтон модуля, вне экранов: экран можно сменить, чтение продолжится. Web Audio не используем: на iOS при блокировке он останавливается.
- **Следующий аят — по `ended`.** В обработчике того же элемента `src` меняется на следующий файл и сразу, синхронно, зовётся `play()`.
  - Таймеров нет: в фоне их душат (Chrome — до раза в минуту, iOS — останавливает).
  - Тест ловит любой `setTimeout` и `setInterval` из модулей плеера.
- **Предзагрузка.**
  - Пока играет аят, следующий скачивается `fetch` (свой адрес, без cookie и referrer) в `Blob`, затем — `blob:` URL.
  - По `ended` `src` = готовый blob: нет паузы на сеть, которая в фоне просыпается медленно. Второго играющего элемента нет.
  - Не успело, 404 или ответ не `audio/*` (например, `index.html` сайта) — играет прямой адрес.
  - Держим не больше двух blob: текущий и следующий. Остальные освобождаются (`revokeObjectURL`).
  - CSP `media-src 'self' blob:` это уже разрешает.
- **Повтор аята** — тот же `src`, `currentTime = 0`, `play()`.
- **Первый `play()`** — только из нажатия. Дальше браузер разрешает тому же элементу.
- **Media Session.**
  - `metadata`: `title` «Сура аль-Бакара · аят 255» (kk — «2-сүре · 255-аят»), `artist` — кари, `album` «AI Ustaz».
  - Ни арабского текста аята, ни арабского имени суры (правило 9). Если транслит вдруг арабский — берётся номер.
  - Обложки нет: растр запрещён `check-dist`.
  - Действия: `play`, `pause`, `previoustrack`, `nexttrack`, `stop`, `seekto`; также `playbackState` и `setPositionState`.
  - `seekbackward`/`seekforward` не задаём: тогда iOS показывает ⏮ ⏭, а не ±10 с.
  - Неизвестное браузеру действие пропускается, остальные работают.

### 2.4. Запись и проверка аята (агент записи и проверки; `app/src/quran-check/` и `speech/`)

**Поток на экране `проверкаАята` (финал после ревью 19.11.2026).**
1. Если частей больше одной — сверху **крупно только текущая часть**: срез токенов `разборАята` через те же пробелы
   (байты дословные, номер аята рядом — это часть аята, правило 8), сразу под ней — запись. Весь аят — свёрнутым блоком
   «Весь аят»: раскрытый, он целиком, текущая часть — мягким фоном (не только цветом). Аят из одной части — целиком.
   Так «Записать» на 2:255 и 2:282 — в первом экране, а текущая часть видна рядом со «Стоп» (раньше на 2:282 до кнопки
   было 3+ экрана прокрутки). Закреплённый низ `<Экран низ>` не использовали: экран с меню (не фокусный), а запись,
   «Послушать себя» и итог проверки — одна карточка `<ПанельЗаписи>`, общая с уроками.
2. «Записать» — авто-стоп за 0,5 с до предела (19,5 с): клиент и сервис отбрасывают запись > 20,0 с, а AAC на iOS
   добавляет ~0,05 с. Запись только в памяти страницы; при уходе стирается. Фокус: после «Записать» — на «Стоп», после
   «Стоп» — на «Послушать себя»; «Запись идёт» объявляется один раз (role=status).
3. «Послушать себя».
4. «Сравнить с кари» — только если `доступныйИсточник()`: играет аят целиком, частей у пофайлового набора нет.
   Запись и «Послушать себя» **останавливают** плеер (не пауза): мини-плеер с ▶ исчезает, обработчики Media Session
   снимаются — кари не зазвучит в микрофон ни с экрана, ни с экрана блокировки.
5. «Проверить» — **только** при `проверкаГолосомВключена()`: **на batr.kz — никогда; на aiustaz.pro и www — по имени
   хоста, в той же сборке, что выкатывается на batr.kz (решение владельца 19.11.2026, правка d4e673a)**; на других адресах
   — только сборка с `EXPO_PUBLIC_SPEECH_CHECK=1`. Плашка прототипа там — «Прототип: проверка голоса ИИ — черновик, может
   ошибаться», пояснение — «Запись остаётся на устройстве, пока вы не нажмёте „Проверить“». Согласие, ИИ-предупреждение
   QML, «запись уйдёт на сервер в Казахстане и будет удалена сразу» — как в `<ПроверкаГолосом>`. e2e-quran 7б проверяет
   одну сборку на хостах aiustaz.pro и batr.kz.
6. Слова замечаний — мягкий фон в тексте и строкой «Отмечены слова: 11 — проверьте себя» (для диктора тоже).

**Части и 20 с** (`quran-check/parts.ts`, черновик политики — утверждает устаз, §3).
- База — знаки ۘ ۗ ۖ ۚ; соседние части объединяются, пока оценка ≤ 15 с; через ۘ — никогда.
- Часть без знаков режется, **только если не помещается в предел сервиса** (оценка > 20 с; раньше — > 15 с): по всему
  Корану 9128 частей, вынужденных остановок 499 (было 1289).
- Места вынужденных остановок выбраны по оценке длительности, без смысла, поэтому экран **не советует**, где
  остановиться: «Здесь нет знака остановки. Прочитайте выделенное; где остановиться и с чего начать — уточните у
  устаза». TODO, когда устаз утвердит места: список `сура:аят:слово` в `content/` с проверкой в `check_content` вместо
  оценки.

**Эталон для сервиса — нумерация слов (сделано).**
- Части считаются в **uthmani-словах с 1** (`text.ts`; совпадают со словами фонетической копии).
- `speech/aiustaz_speech/reference.py`:
  1. `uthmani_from` / `uthmani_words` — **прямой срез uthmani-слов фонетической копии** с 1:
     `' '.join(слова[с - 1 : с - 1 + n])`; диапазон проверяется — выход за аят → 400;
  2. старые `word_from` / `words` (imlaey-слова с 0) переводятся картой `imlaey2uthmani` (совместимость; разрез
     «يَٰٓأَيُّهَا» пополам → 400);
  3. клиент (`speech/fields.ts`, `quran-check`) шлёт только `uthmani_from`/`uthmani_words`.
- **Подсветка замечаний.** Сервис отдаёт номер uthmani-слова замечания (`слово`, с 1, по всему аяту); клиент подсвечивает
  слово по нему в копии для показа. `позиция` и `фрагмент` (фонетический текст) на экран не идут, фонемы — никогда.

**Правило 7.**
- Только «Проверьте себя» и «Подсказка», не больше 3; плохой звук — не ошибка.
- **`kinds`** — что ученик уже прошёл по прогрессу уроков (функция `видыПоПрогрессу(прогресс)` — черновик, сверить с программой курса). Если не пройдено ничего — не передавать `kinds` нельзя: передавать минимальный набор (буквы и огласовки), чтобы не ругать за мадды и гунну, которых ещё не было.
- Нет замечаний — «Мы не услышали расхождений. Проверка ИИ может ошибаться» (без «Верно»).

**Приватность.** Запись не сохраняется: ни `localStorage`, ни IndexedDB, ни сервер — кроме разбора по «Проверить» с удалением сразу. Детских и женских записей мы не храним вовсе. В LLM — ничего.

**Тексты подсказок** — `speech/hints.ts` (черновик, ru и kk): они уже годятся для аятов, новых религиозных текстов не нужно.

#### Связность букв (Chromium)
- **Приём.** Кусок цвета — всегда ЦЕЛАЯ буква со всеми знаками (огласовки, шадда, сукун, мадда, малые мимы), без пробелов; соседние буквы слова с одним кодом — один кусок. Внутри слова — `<span style="color">` (только цвет: шрифт, размер и начертание те же). Chromium (LayoutNG) формирует абзац целиком и лишь красит глифы — связки и огласовки остаются на месте.
- **Проверено.** Опыт на 6 словах (ٱلرَّحْمَـٰنِ, ٱلضَّآلِّينَ, يُنفِقُونَ, أُو۟لَـٰٓئِكَ, هُدًۭى, حَبْلٌۭ مِّن): ширина слова с кусками другого цвета = без них (разница ≤ 0,05 px; при разрыве формы буквы стали бы отдельными, слово — шире), снимки крупно (`design/shots/quran-views/связность-chromium-опыт.png` в песочнице). e2e: ширина каждой группы «слово + знаки» на странице 2 с цветами = без цветов (36 групп, макс. 0,05 px). WebKit (iOS Safari) в окружении нет — проверить на телефоне.

#### Шрифт
- Остаёмся на **Amiri Quran** (OFL): рисует весь текст Tanzil, ۝ с номером собирает в один знак. **KFGQPC Uthmanic Script HAFS** даёт вид «как в мусхафе», но его условия (бесплатно, без изменений; отдельного разрешения на встраивание в приложение мы не нашли) не проверены, и он рассчитан на свою кодировку текста KFGQPC, а не Tanzil (часть знаков рисуется иначе). **Не подключали.** Предложение: запросить у KFGQPC письменное разрешение и сверить шрифт со всеми 6236 аятами копии для показа (как test-quran для Amiri), либо DigitalKhatt (OFL) — после такой же сверки.

## 3. Вопросы владельцу и устазу
1. ~~**Какая выгрузка Tanzil — для показа.**~~ **Решено (финал 19.11.2026):** взята выгрузка tanzil.net с теми же знаками
   и с `tatweel=true, stanween=true` — татвиль и малые мимы после танвина (икляб, идгам, ихфа) на месте, без знаков-токенов
   она побайтно равна фонетической копии. sha256 `af9311c5…2916`, якорь — `quran_common.ЭТАЛОН_SHA256_ПОКАЗА`.
2. **Права на чтение Мишари Рашида аль-Афаси.** Нужны условия и разрешение, а также где лежат файлы (свой сервер в РК,
   `aiustaz.pro/aiustaz-audio/…`). До этого — «Аудио появится после разрешения кари». Плеер готов. **Перед «разрешено:
   true»** (ревью): завести манифест аудио — id файла → sha256, длительность, сура:аят; `check_audio.py` должен требовать
   его, плеер — брать адрес из манифеста (с хэшем в имени); файл бисмиллы — в поле `бисмилла` (у Афаси обычно отдельный).
   Иначе перепутанный файл зазвучит под подсветкой другого аята, а суры (кроме 1 и 9) — без басмалы.
3. **Где делить длинный аят для записи (устаз).** Делим по ۘ ۗ ۖ ۚ (не по ۙ ۛ ۜ). Без знака режем, только если часть
   не помещается в 20 с: 499 мест на весь Коран; экран не советует, где остановиться, — «уточните у устаза». Нужен список
   утверждённых мест `сура:аят:слово`. Поднимать ли предел сервиса для аятов (нагрузка на CPU)?
4. **Транслитерация имён сур.** ru — черновик (плашки на списке, суре и экране записи). kk — нужен редактор-носитель и
   словарь ДУМК (сейчас kk показывает номер и арабское имя). Синонимы поиска (латиница, «Ясин») — тоже черновик.
5. **Объём сборки.** `dist` ≈ 3,3 МБ (Коран 1,7 МБ, грузится по одной суре). gzip на batr.kz не проверен — JSON
   сжимается в 4–5 раз. Бюджет «всего» (4770 КБ) — предлагаем опустить, см. §2.5.
6. **Плеер на телефонах с выключенным экраном.** Нужен живой прогон: Android Chrome и iPhone (Safari и ярлык «На экран
   Домой»), по таблице §2.3.1. Без него поведение iOS в фоне — оценка.
7. **Отдача статики (зона batr-world, не наша; только предложение).** `location /aiustaz/` делает `try_files … index.html`:
   пропавший файл суры старой вкладки приходит как HTML с кодом 200 — экран теперь пишет «Файл не найден, обновите
   страницу». Предлагаем: `location /aiustaz/quran/ { try_files $uri =404; expires 1y; add_header Cache-Control
   "public, immutable"; }` (файлы с хэшем) и `location /aiustaz-audio/` (audio/mpeg, Accept-Ranges, долгий кэш) — когда
   будут права на записи.
8. **Без сети.** Сура, которую не открывали, без сети — «Нет связи / Повторить»; перезагрузка без сети не работает
   (своего Service Worker нет). Предложение: на aiustaz.pro — SW со своим scope и кнопка «Сохранить Коран для чтения без
   сети (1,7 МБ)» в «Ещё»; на batr.kz SW не ставить. Не делали: решение о SW на своём домене — за владельцем.
9. **Диктор и арабский текст.** Текст аята теперь доступен экранному диктору пользователя (это его вспомогательная
   технология, не TTS приложения — правило 3 не нарушается). Подтвердите, что так оставляем.
10. **Межстрочный ×1,8** выбран по снимкам (знаки над и под строкой не налезают). Посмотреть вместе с кари на телефоне.
11. **Цвета таджвида (устазу, §2.8).** Проверить правила и спорные места: калькаля и сыля в конце аята как при остановке;
    знак мадда в конце аята — мунфасиль; يَٰٓأَيُّهَا — мунфасиль; у танвина красится вся буква; идгам накис ط→ت,
    мукатта‘ат (ихфа/идгам внутри названий букв, ‘ин 4 или 6), имала/ишмам/ташиль — пока без цвета; набор цветов и названия
    (ru, kk — черновик). До проверки — плашка «Цвета таджвида — черновик».
12. **Шрифт «как в мусхафе» (владельцу).** KFGQPC Uthmanic Hafs — только с письменного разрешения KFGQPC и после сверки
    со всеми аятами; пока Amiri Quran. Переносы строк как в мусхафе требуют данных строк (layout), которых в открытых
    данных с подходящей лицензией нет — сейчас «страницы как в мусхафе, строки — по ширине экрана».
