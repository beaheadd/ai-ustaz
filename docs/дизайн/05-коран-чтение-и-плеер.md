# 05. Коран: полный текст, чтение, плеер, запись и проверка (19.11.2026)

**Запрос владельца (19.11.2026):** «Коран полностью, все аяты … Коран нужно Мишари Ар-Рашид добавить аудио, добавить плеер нужно, чтобы можно было слушать, и когда экран выключен. Чтобы Коран мог читать и проверить, как он читает … заходишь и читаешь любой аят, и записываешь голос и проверяешь, где ошибки.»

**Что в этом документе.** Данные Корана уже готовы (раздел 1). Раздел 2 — контракт для трёх следующих агентов: плеер, запись и проверка, экраны. Хадисы, тафсир, переводы смыслов и права на аудио Алафаси ведёт **отдельный процесс**. Здесь их нет: ни перевода, ни тафсира, ни хадисов, ни аудиофайлов.

Жёсткие правила (CLAUDE.md), которые касаются этой работы:
- **правило 1** — Коран только дословно из копии Tanzil для показа;
- **правило 3** — только живые записи кари по договору, без синтеза;
- **правило 5** — без ИИ-тафсира;
- **правило 7** — только «Проверьте себя» и «Подсказка»;
- **правило 8** — неверный вариант аята не показывать;
- **правило 9** — без текста Корана в уведомлениях;
- **правило 11** — пояснения с плашкой «черновик»;
- **приватность голоса**;
- **QML** — проверка голосом только в сборке своего домена.

## 1. Что сделано (данные)

### 1.1. Копия Tanzil для показа
- **Файл.** `content/quran/quran-uthmani-marks.xml` — побайтная копия, загружена с tanzil.net 19.11.2026.
  - Tanzil Uthmani v1.1, XML, 114 сур, 6236 аятов.
  - sha256 `33f4113df84c1bab0ee2eb69616139fda619bdd56fc163a72532daaf0431bf57`.
  - Параметры загрузки: `quranType=uthmani, outType=xml, marks=true, sajdah=true, rub=true`.
- **sources.json.** Запись `tanzil` — копия **для показа**, с путём, sha256, датой и параметрами загрузки. Отдельная запись `tanzil-phonetic` — копия без знаков из `quran-transcript` 0.6.4 (sha256 `dc4e68cb…3f07`): **только фонетика и выравнивание**, на экран не выводится. Блок копирайта Tanzil не тронут.
- **Где копирайт.** Блок условий Tanzil лежит в каждом производном файле (индексе и каждой суре). Ссылка на tanzil.net — в «Лицензиях».

### 1.2. Чем две копии отличаются (сверено по всем 6236 аятам)
- **Знаки — отдельными токенами через пробел.** Они есть только в копии для показа:

  | Знак | Сколько |
  |---|---|
  | ۖ | 1682 |
  | ۗ | 603 |
  | ۚ | 1972 |
  | ۛ | 12 |
  | ۙ | 68 |
  | ۘ | 22 |
  | ۜ | 5 |
  | ۞ | 199 (всегда в начале аята) |
  | ۩ | 15 (всегда в конце аята) |

  Ещё 2 раза ۜ стоит внутри слова (сакта по начертанию).
- **Слова.** Если убрать знаки-токены, слова обеих копий совпадают **по числу и порядку во всех аятах**. Поэтому номер слова (с 1, без знаков) одинаков в обеих копиях.
- **Начертание слов различается.** В фонетической копии есть то, чего нет в копии для показа:
  - татвиль ـ перед надстрочным алифом — 5924 раза;
  - малые мимы после танвина: U+06ED — 4708 раз, U+06E2 — 1935 раз.

  Это вариант выгрузки tanzil.net (2007-2024 против 2007-2026), а не наши правки. Для показа берём только копию со знаками. Не «исправляем» её и не смешиваем копии — вопрос владельцу в §3.
- **В аль-Фатихе** отличие одно: татвиль в 1:1–1:4.

### 1.3. Производные (статические файлы сборки)
- **Как собирается.** `python3 -I -B tools/quran/build_quran.py` (без сети, `--check` — только сверка) пишет:
  - `app/public/quran/NNN.<sha256[:20]>.json` — 114 сур. Поля:
    - `формат: 1`, `источник: 'tanzil-uthmani-1.1'`, `копия: 'показ'`, `файлИсточника`, `sha256Источника`;
    - `сура`, `имя` (арабское, атрибут XML), `аятов`;
    - `бисмилла` — атрибут XML или `null` (у сур 1 и 9);
    - `аяты: [{ аят, текст }]` — дословно;
    - `копирайт`.
  - `app/public/quran/index.<sha256[:20]>.json` — индекс. Запись суры: `{ сура, имя, аятов, файл, sha256, транслит: { ru, kk } }`, плюс `статусТранслита: 'черновик'` и `копирайт`.
  - `app/src/quran/manifest.generated.ts` — `МАНИФЕСТ_КОРАНА`: имя и sha256 индекса. **Текста Корана в JS нет.**
- **Как попадает в сборку.** Expo `export` копирует `app/public/` в корень `dist/` как есть. Адреса — `/aiustaz/quran/…` (baseUrl). Хэш в имени нужен `check-dist` (SW batr.kz кэширует файлы по адресу навсегда). `release-batr.sh` копирует `dist/` целиком — `quran/` уходит вместе со сборкой; `.gitignore` batr-world её не режет (проверено `git check-ignore`).
- **Транслитерация имён сур.** ru — черновик для устаза и редактора: «аль-Фатиха», «аль-Бакара»… Это транслитерация арабского имени, не перевод смыслов. **kk пока `null`** («если сомневаетесь — только номер и арабское имя»): экран показывает «N-сүре» и арабское имя. Транслитерации правятся в `tools/quran/quran_common.py` (`ТРАНСЛИТ_RU`), затем пересборка.

### 1.5. Показ аль-Фатихи
- **Откуда берётся.** «Коран» (`#/quran`) и «Как объясняем» (`#/how`) показывают аль-Фатиху из `content/fatiha-demo.json`. Генератор `tools/build_content.py` теперь берёт её из **копии для показа**.
- **Что изменилось.** Аяты 1:1–1:4 — без татвиля, новые `хеш` и `файл: quran-uthmani-marks.xml`. Строка `коран-копия` на экране: «Копия для показа — со знаками остановки, саджды и руб‘ аль-хизба».
- **Слова примеров.**
  - Сверяются с копией для показа: `check_content` сравнивает их побайтно, слово берётся по номеру через `split(' ')`.
  - В аль-Фатихе знаков-токенов нет, поэтому номера слов не сдвинулись.
  - Каталог ошибок (§13) цитирует слова по фонетической копии, с татвилем. Генератор сопоставляет цитату со словом Tanzil **без учёта татвиля** и подставляет в текст объяснения слово **дословно из копии для показа** (`цитаты_по_tanzil`). Сам каталог не менялся.
- **Фонетическая копия** остаётся речевому сервису (`speech/`, `quran_transcript`).

## 2. Контракт

### 2.1. Маршруты (делает агент экранов; `app/src/engine/routes.ts`)

| Экран (`ИмяЭкрана`) | hash | Параметры | Вкладка | Меню |
|---|---|---|---|---|
| `коран` (есть) | `#/quran` | — | `коран` | видно (корень раздела) |
| `сура` (новый) | `#/quran/sura?n=2&a=255` | `{ номер: number /*1…114*/; аят?: number /*1…аятов*/ }` | `коран` | **видно** (не в `ФОКУСНЫЕ`, без `низ`) |
| `проверкаАята` (новый) | `#/quran/check?n=2&a=255&p=1` | `{ номер; аят; часть?: number }` | `коран` | видно; запись — встроенной `<ПанельЗаписи>`, без закреплённого низа |

- **`routes.ts`.** Сейчас путь — один сегмент, параметр — один сегмент после (`#/lesson/3`). Нужно:
  1. путь из двух сегментов: `ПУТИ.сура = 'quran/sura'`, `ПУТИ.проверкаАята = 'quran/check'`; сопоставлять самый длинный путь;
  2. параметры query-строкой после `?`: `n`, `a`, `p` — только цифры. `вХэш` пишет `a` и `p`, только если они заданы.

  `#/quran` без хвоста — по-прежнему `коран`. Неверные `n`/`a` дают `null` (как сейчас). Аят больше числа аятов суры проверяет экран после загрузки: начинает с 1 и пишет «нет такого аята».
- **Глубокая ссылка.** `#/quran/sura?n=2&a=255` должна давать стек `[главная, коран, сура]`: «назад» → список сур. Если это сложно, `[главная, сура]` (вкладка «Коран» из `ВКЛАДКА_ЭКРАНА`) тоже допустимо — решает агент экранов.
- **Список сур (`#/quran`)** заменяет нынешнюю аль-Фатиху. Каждая строка: номер, транслитерация (ru; для kk — «N-сүре»), арабское имя (`АрабскийТекст`), число аятов. Поиск по номеру и транслитерации — по желанию. «Как объясняет» и «Источник и условия Tanzil» остаются.
- **Без текста Корана:** в `document.title`, заголовке экрана, уведомлениях и Media Session. Заголовок — «Сура аль-Бакара (2)».

### 2.2. Данные (готово; `app/src/quran/`)

```ts
import { useИндексСур, useСура, загрузитьИндексСур, загрузитьСуру, сураИзКэша, индексИзКэша } from '../quran/data';
import { разборАята, словаАята, числоСлов, остановкиАята, частиПоОстановкам, ЗНАКИ, ОСТАНОВКИ_ДЛЯ_ЧАСТЕЙ } from '../quran/text';

useИндексСур()   → ({ состояние: 'загрузка' } | { состояние: 'нет'; нетСвязи: boolean; причина } | { состояние: 'есть'; данные: ИндексСур }) & { повторить() }
useСура(н | null) → то же с данными СураКорана; null — ничего не грузить
загрузитьСуру(н): Promise<{ ок: true; данные: СураКорана } | { ок: false; причина: 'нет-связи' | 'сбой-сервера' | 'нет-файла' | 'не-прошло-сверку' }>
сураИзКэша(н): СураКорана | null            // уже загруженное, без ожидания (плеер — следующая сура)

ИндексСур  { сур: 114; аятов: 6236; суры: ЗаписьСуры[]; статусТранслита; копирайт; источник; файлИсточника; sha256Источника }
ЗаписьСуры { сура; имя /*арабское*/; аятов; файл; sha256; транслит: { ru: string | null; kk: string | null } }
СураКорана { сура; имя; аятов; бисмилла: string | null; аяты: АятКорана[]; копирайт; источник; файлИсточника; sha256Источника }
АятКорана  { сура; аят; текст }               // текст — дословно, со знаками-токенами
```

- **Состояния экрана.**
  - `нетСвязи: true` (`нет-связи`, `сбой-сервера`) — «Нет связи» и «Повторить».
  - `false` (`нет-файла`, `не-прошло-сверку`) — «Текст не прошёл сверку — не показываем», и ни одного аята.

  Неудачи не кэшируются. Таймаут запроса — 20 с.
- **Как грузится.** Одна сура — один запрос: аль-Бакара ≈ 114 КБ, обычно 1–20 КБ. Цепочка сверки sha256: манифест → индекс → сура. На телефоне (натив) относительного адреса нет — TODO: адрес своего домена или файлы в пакете.
- **Бисмилла** (`сура.бисмилла`) рисуется перед аятом 1 **отдельной строкой, без номера**: это не аят. У суры 1 бисмилла — сам аят 1:1, у суры 9 её нет.
- **Номер аята** — отдельный элемент рядом с текстом (как в `АятСоСловами`). В строку Корана ничего не вставлять: ни ۝, ни цифры.
- **`text.ts`** (чистые функции, без импортов).
  - `разборАята(текст)` → токены `{ вид: 'слово', текст, номерСлова }` или `{ вид: 'знак', текст, знак, послеСлова }`. Склейка токенов через пробел равна строке. Знаки остаются в тексте и рисуются Amiri Quran — ничего не вырезать.
  - **Номер слова — по `разборАята`**, без знаков-токенов. В старом `АятСоСловами` номер — индекс `split(' ')`, вместе со знаками: для полного Корана брать `разборАята`.
  - `частиПоОстановкам(текст)` → `{ номер, словоС, слов, токенС, токенПо, знакВКонце }[]`. Где можно остановиться — ۘ ۗ ۖ ۚ (**черновик политики, утверждает устаз**). Не делим по ۙ (не останавливаться), ۛ (пара), ۜ (сакта), ۞, ۩.
  - **Статистика:** самый длинный аят — 2:282 (128 слов). Частей длиннее 20 слов — 209, длиннее 30 — 21. Самые длинные — 24:61 и 4:23, по 49 слов.
- **Длинные суры.** Аль-Бакара — 286 аятов: список — виртуализированный (`FlatList`/`windowSize`) или по страницам. Переход к `a` — прокрутка к аяту. Пока Amiri не загружен, текст прозрачен (как в `АятСоСловами`).

### 2.3. Плеер (агент плеера; `app/src/audio/`)

**Источник — `content/audio-sources.json`** (создаёт агент плеера). Пока там одна запись, и `разрешено: false`:
```json
{ "версия": "2026.11", "источники": [ {
  "id": "alafasy",
  "кари": { "ru": "Мишари Рашид аль-Афаси", "kk": "Мишари Рашид әл-Афаси", "ar": "مشاري راشد العفاسي" },
  "база": "/aiustaz-audio/alafasy",
  "шаблон": "{sura3}{aya3}.mp3",
  "бисмилла": null,
  "разрешено": false, "дата_разрешения": null, "условия": null,
  "атрибуция": { "ru": "…", "kk": "…" },
  "примечание": "Права на записи выясняет владелец (отдельный процесс). Файлов в репозитории и сборке нет." } ] }
```
- **Поля.**
  - `база` — путь **на том же домене** (CSP `media-src 'self'`; никаких внешних CDN). Файлы лежат **вне `dist/`** на сервере своего домена (nginx `location /aiustaz-audio/`): весь Коран — сотни МБ, в git batr-world им не место.
  - `шаблон` — `{sura3}{aya3}` = `002255` (как у пофайловых наборов по аятам).
  - `бисмилла` — файл бисмиллы перед сурой, если у источника она отдельно; иначе `null`.
  - kk-подпись — черновик. Арабское имя кари — проверить у владельца.
- **Показ.** Источник виден ученику, только если одновременно:
  - `разрешено: true`, есть `дата_разрешения` и `условия` (как `media.json`);
  - страница **не** на batr.kz — файлов там нет.

  Иначе вместо кнопки ▶ — строка «Чтение кари появится после разрешения» (без сроков). Синтеза нет никогда (правило 3).
- **Проверка в `check_content`** (агент плеера добавляет `tools/audio/check_audio.py`):
  - `разрешено` — только с датой и условиями;
  - `база` — относительная, с `/`, без схемы;
  - в шаблоне есть `{sura3}` и `{aya3}`;
  - аудиофайлов в `app/public` нет.
- **API.**
  ```ts
  type Очередь = { сура: number; сАята: number; поАят: number; повторАята: number /*1…N, по умолчанию 1*/;
                   повторОтрезка: boolean; бисмиллаПеред: boolean };
  плеер.играть(очередь)  плеер.пауза()  плеер.продолжить()  плеер.стоп()  плеер.следующий()  плеер.предыдущий()  плеер.кАяту(н)
  useПлеер() → { состояние: 'стоп' | 'загрузка' | 'играет' | 'пауза' | 'ошибка'; текущий: { сура; аят; повтор: number; из: number } | null;
                 ошибка?: 'нет-источника' | 'нет-связи' | 'не-поддерживается'; источник: ИсточникЧтения | null }
  доступныйИсточник(): ИсточникЧтения | null;   адресАята(источник, сура, аят): string
  ```
- **Плеер живёт вне экранов.** Экран размонтируется при уходе (`ARCHITECTURE.md`), поэтому плеер — синглтон модуля с одним `HTMLAudioElement`. Мини-панель (по желанию) — в `App.tsx` над нижним меню. Подсветка текущего аята на экране суры — через `useПлеер().текущий`.
- **Фон и выключенный экран (веб).**
  - Одна `<audio>`, следующий аят — сменой `src` по `ended`. Web Audio не использовать: на iOS при блокировке он останавливается.
  - Следующий файл — предзагрузка во второй элемент или `fetch` в кэш.
  - Первый `play()` — только из нажатия.
  - Media Session:
    - `metadata` — `title` «Сура аль-Бакара · аят 255» (без арабского текста, правило 9), `artist` — имя кари, `album` «AI Ustaz»;
    - действия — `play`, `pause`, `previoustrack`, `nexttrack`, `stop`, `seekto`, а также `setPositionState`;
    - обложки нет: растр запрещён `check-dist`, SVG поддерживают не все.
  - Проверить на Android Chrome (экран выключен, 3+ аята подряд) и iOS Safari. Если iOS рвёт очередь между файлами — записать как ограничение. Нативно — `expo-audio` с фоновым режимом (TODO).
- **Без музыки, без звуков интерфейса, без автозапуска.** Повтор аята ×N — для заучивания, не «награда».

### 2.4. Запись и проверка аята (агент записи и проверки; `app/src/quran-check/` и `speech/`)

**Поток на экране `проверкаАята`.**
1. Аят крупно. Если частей больше одной — части по `частиПоОстановкам`, текущая подсвечена токенами `токенС…токенПо` в **целом** аяте. Обрезок текста отдельно как «аят» не показывать.
2. «Записать» — `<ПанельЗаписи максДлительностьМс={20000}>`. Запись только в памяти страницы; при уходе стирается.
3. «Послушать себя».
4. «Сравнить с кари» — только если `доступныйИсточник()`: играет аят целиком, частей у пофайлового набора нет.
5. «Проверить» — **только** при `проверкаГолосомВключена()`, то есть сборка своего домена (`EXPO_PUBLIC_SPEECH_CHECK=1 MUGALIM_TARGET=own-domain`). На batr.kz кнопки нет. Согласие, ИИ-предупреждение QML, «запись уйдёт на сервер в Казахстане и будет удалена сразу» — как в `<ПроверкаГолосом>`.

**Части и 20 с.**
- Соседние короткие части объединять, пока оценка ≤ 20 с. Оценка — черновик: ≈ 1 слово в секунду для тартиля. Уточнить по записям кари.
- Если часть длиннее и знаков нет (209 частей > 20 слов):
  - запись > 20 с сервис не примет — клиент уже отвечает «плохой звук: длинно», это не ошибка;
  - предложить вынужденную остановку там, где кончилось дыхание, и **возврат на слово-два назад** — так учат устазы.

  Это **черновик политики, утверждает устаз** (§3).

**Эталон для сервиса — ⚠ нумерация слов.**
- Части считаются в **uthmani-словах с 1** (`text.ts`; совпадают со словами фонетической копии).
- Сервис сейчас передаёт `word_from` в `Aya.get_by_imlaey_words(start, window)` из `quran_transcript`. Там **imlaey-слова с 0**, а imlaey-слов бывает больше: «يَٰٓأَيُّهَا» → «يا أيها».
- Уже сейчас `app/src/speech/check.ts` → `эталонЗадания` шлёт `слова.с` (uthmani с 1) как `word_from`. Это **скрытая ошибка**: в данных уроков фрагментов со `слова` пока нет.
- Нужно в `speech/`:
  1. новые поля формы `uthmani_from` (с 1) и `uthmani_words`. Сервис переводит их в imlaey через `Aya(с, а)._encode_imlaey_to_uthmani().imlaey2uthmani` (карта imlaey → uthmani) и зовёт `get_by_imlaey_words(старт0, окно)`. Старые `word_from`/`words` — как есть, для совместимости;
  2. клиент шлёт `uthmani_from`/`uthmani_words`;
  3. тест: 2:2 части, 2:21 («يَٰٓأَيُّهَا»), 1:7 и аят с ۞ в начале.
- **Подсветка замечаний.** Сервис отдаёт `позиция` и `фрагмент` в **фонетическом** тексте (с татвилем и малыми мимами), а на экране — копия для показа. Фрагмент ищется в тексте на экране (`speech/answer.ts`) и в аятах с этими знаками часто не найдётся → «в одном месте». Нужно, чтобы сервис отдавал **номер uthmani-слова** замечания (`слово`, с 1, в нумерации полного аята). Клиент подсвечивает слово по `номерСлова` из `разборАята`. Фонемы на экран — никогда.

**Правило 7.**
- Только «Проверьте себя» и «Подсказка», не больше 3; плохой звук — не ошибка.
- **`kinds`** — что ученик уже прошёл по прогрессу уроков (функция `видыПоПрогрессу(прогресс)` — черновик, сверить с программой курса). Если не пройдено ничего — не передавать `kinds` нельзя: передавать минимальный набор (буквы и огласовки), чтобы не ругать за мадды и гунну, которых ещё не было.
- Нет замечаний — «Мы не услышали расхождений. Проверка ИИ может ошибаться» (без «Верно»).

**Приватность.** Запись не сохраняется: ни `localStorage`, ни IndexedDB, ни сервер — кроме разбора по «Проверить» с удалением сразу. Детских и женских записей мы не храним вовсе. В LLM — ничего.

**Тексты подсказок** — `speech/hints.ts` (черновик, ru и kk): они уже годятся для аятов, новых религиозных текстов не нужно.

## 3. Вопросы владельцу и устазу
1. **Какая выгрузка Tanzil — для показа.** Сегодняшняя копия (2007-2026, параметры выше) — без татвиля перед надстрочным алифом и без большинства малых мимов после танвина (U+06ED/U+06E2: подсказки икфа, икляба и идгама в начертании). В фонетической копии 2024 года они есть. Нужна ли для тренера таджвида выгрузка с ними — тогда скачать заново с теми же знаками, но с этими параметрами tanzil.net? Текст сами не правим.
2. **Права на чтение Мишари Рашида аль-Афаси.** Нужны условия и разрешение, а также где лежат файлы (свой сервер в РК). До этого — «появится после разрешения».
3. **Где делить длинный аят для записи.** Предлагаем по ۘ ۗ ۖ ۚ; что делать с частями > 20 с без знаков (вынужденная остановка и возврат на слово назад?) — решает устаз.
4. **Транслитерация имён сур.** ru — черновик. kk — нужен редактор-носитель и словарь ДУМК (сейчас kk показывает номер и арабское имя).
5. **Объём сборки.** `dist` вырос до ≈ 3,1 МБ (Коран 1,7 МБ, грузится по одной суре). gzip на batr.kz не проверен (HANDOFF) — JSON сжимается в 4–5 раз.
