# 07. Уведомления о времени намаза

**Запрос владельца (20.11.2026, скрин уведомлений Muslim Pro):** «Нам тоже нужно добавить уведомления, чтобы правильные,
красивые уведомления время намаза приходило к клиенту.»

**Решение ведущего 20.11.2026:** Web Push (VAPID) со своего сервера в РК, без Firebase SDK и аналитики; время считает
телефон, на сервер — только расписание без координат; только на aiustaz.pro. Контракт кода — `app/ARCHITECTURE.md`
(«Уведомления о времени намаза»), сервер — `server/README.md`.

## 1. Что получает человек

| Когда | Заголовок | Текст | Кнопки |
|---|---|---|---|
| Начало времени намаза | `Аср · 14:39` | `Наступило время намаза · Алматы. Следующий — Магриб в 16:28` | «Время намаза» → `#/prayer`, «Кибла» → `#/qibla` |
| Пятница, зухр | `Джума · 13:05` (kk: `Жұма намазы · 13:05`) | то же | то же |

| Напоминание за N мин | `Через 10 мин — Аср (14:39)` | `Алматы` | — |
| За 3 дня до конца расписания (один раз, **без звука**) | `AI Ustaz` | `Откройте AI Ustaz, чтобы обновить время намаза` | → `#/notifications` |

kk (черновик для редактора-носителя и словаря ДУМК): `Екінті · 14:39` — `Намаз уақыты кірді · Алматы. Келесі — Ақшам,
16:28`; напоминание — `10 минуттан кейін — Екінті (14:39)`; кнопки «Намаз уақыты», «Құбыла»; обновление — `Намаз уақытын
жаңарту үшін AI Ustaz-ты ашыңыз`. Названия намазов — как в приложении (muftyat.kz: Таң, Күн шығуы, Бесін, Екінті,
Ақшам, Құптан). **Вопрос редактору:** «Жұма намазы» (в задании было «Жума намазы» — по-казахски пишется «Жұма»).

Значок — эмблема-фонарь (`pwa/icon-192`), в строке состояния — монохромный (`pwa/icon-mono-512`). `tag` —
`aiustaz-<намаз>-<день>` и `aiustaz-soon-<намаз>-<день>`: повтор того же намаза заменяет уведомление, а не копится.
Звук — системный звук уведомлений телефона. Макет шторки Android (HTML → PNG) и снимки экрана настроек 412×800 ru/kk —
в отчёте задачи (растры в git не кладём).

**Чего нет и не будет (CLAUDE.md):** текста Корана, хадисов и их пересказа, призывов («прочитайте суру…»), фраз о
действительности намаза, серий, рейтингов, наград, эмодзи-мечетей, музыки. Своего азана нет: «без музыки», а запись
азана кари — только по договору (будущая опция: «Звук: азан кари <имя>» с файлом в РК, только по выбору человека).
Тексты собирает сервер из шаблонов (`server/push.py`), без LLM.

## 2. Как включают (экран `#/notifications`)

«Ещё» → Настройки → **«Уведомления о намазе»** (подпись — «Включены/Выключены»); на главной — маленький колокольчик
справа от строки следующего намаза (золотой — включены, с чертой — выключены), только если влезает: он стоит поверх
строки и **не меняет высоту карточки** (e2e-home и e2e-notify это сверяют).

1. Переключатель «Присылать уведомления». Браузер ещё не спрашивал — сначала **наше пояснение**: что придёт; координаты
   не уходят, время считает телефон; что и где хранится (сервер AI Ustaz в Казахстане: подписка, язык, город,
   расписание на 30 дней); выключите — удалится сразу; раз в месяц тихое напоминание открыть приложение. Только по
   «Разрешить уведомления» — системный запрос. «Не сейчас» — ничего не происходит.
2. Отказ (или разрешение снято потом) — «Браузер запретил уведомления» и где включить: Android/Chrome (значок слева от
   адреса → «Разрешения» → «Уведомления»), приложение AI Ustaz (настройки телефона → «Приложения» → AI Ustaz →
   «Уведомления»), iPhone («Настройки» → «Уведомления» → AI Ustaz), компьютер. Повторно браузер не спрашиваем.
3. «Какие времена»: Фаджр, Восход (**выключен по умолчанию**: это не намаз — им кончается время фаджра), Зухр, Аср,
   Магриб, Иша — с сегодняшним временем; последний выбранный выключить нельзя.
4. «Напомнить заранее»: Нет · 5 · 10 · 15 · 30 мин — вдобавок к уведомлению в начале времени.
5. Город — тот же, что для времени намаза (`#/prayer-city`).
6. «Проверить уведомление» — сервер шлёт тестовое сразу; строка «Расписание на 30 дней — до 20 декабря».
7. «Так будет выглядеть» — пример с сегодняшним временем; «Что хранится» — приватность.

Не на aiustaz.pro: batr.kz — в «Ещё» вместо строки пояснение «Уведомления о времени намаза — на aiustaz.pro», экран —
ссылка на aiustaz.pro, колокольчика нет, worker не регистрируется (у batr.kz свой service worker со scope «/»;
реклама и чужие скрипты вокруг). iPhone не с экрана «Домой» — объяснение и «Как добавить на экран „Домой“» (`#/install`).

## 3. Приватность

- **Время считает телефон** (тот же расчёт ДУМК, что на главной, `prayer/times.ts`) на 30 дней вперёд. На сервер уходят
  только: подписка push (адрес push-сервиса браузера + ключи шифрования), язык, **название города строкой**, и пункты
  `{at (UTC), key, time "14:39", before, next}`. **Координат нет** — ни города, ни своей точки по геолокации. Сервер
  отклоняет тело с лишними полями (`fields`), проверяет `time = at + before` по UTC+5, ≤ 12 пунктов в сутки, ≤ 31 дня,
  только https-адреса известных push-сервисов (защита от SSRF): fcm.googleapis.com, updates.push.services.mozilla.com,
  web.push.apple.com, *.notify.windows.com.
- **Хранение:** пока уведомления включены. Расписание обновляется при каждом открытии приложения и при смене города,
  языка, намазов, «за N мин». Не открывали почти месяц — одно тихое «обновите время» за 3 дня до конца; ещё через
  30 дней после конца подписка удаляется сама. Подписка, отвергнутая push-сервисом (404/410: разрешение снято,
  приложение удалено), — удаляется при первой отправке.
- **Удаление:** выключить уведомления — подписка и расписание удаляются с сервера сразу (`/api/push/unsubscribe`,
  каскад в БД); в браузере — отписка и снятие worker.
- **Журнал:** только sha256 адреса (32 hex), событие, код ответа — 90 дней. IP не пишем (nginx `access_log off`;
  лимиты — хэш IP на минуту, чистятся через час).
- **Доставка** идёт через push-сервис браузера (Chrome — Google FCM, Safari — Apple): тело зашифровано (aes128gcm),
  подписано нашим VAPID-ключом. Firebase SDK, аналитики, рекламы нет. VAPID-ключи создаются только на сервере.
- **Политика** — `app/public/privacy.html` п. 6 (ru/kk/en, версия 1.1); Data safety — `twa/play/data-safety.md`
  (приблизительное местоположение = название города и идентификатор подписки, по желанию, не передаются).
- На устройстве — `aiustaz:notify.v1`: включено, выбор намазов, «за N мин», когда отправили и до какого числа.
  Адреса подписки там нет (её хранит сам браузер).

## 4. Ограничения платформ (честно)

| Где | Работает? | Что учесть |
|---|---|---|
| Android, Chrome / Edge / Samsung Internet | да | доставка через FCM; `Urgency: high` и TTL 10 мин (намаз) — телефон в «Doze» будится; без сети дольше TTL уведомление не придёт (поздно — не нужно). Агрессивная экономия батареи (Xiaomi, Huawei и др.) может задерживать — совет в FAQ: убрать ограничения для Chrome/AI Ustaz |
| Android, приложение AI Ustaz (TWA) | да | `enableNotifications: true`: Chrome делегирует уведомления приложению (значок и настройки — «AI Ustaz»); Android 13+ спросит разрешение `POST_NOTIFICATIONS` |
| iPhone/iPad, Safari, **с экрана «Домой»**, iOS 16.4+ | да | только у приложения на экране «Домой» (web.push.apple.com); из обычного Safari — нет (объясняем, ведём на `#/install`) |
| iPhone, iOS < 16.4 | нет | честное «обновите iOS» |
| Встроенные браузеры (Instagram, Telegram, WhatsApp, TikTok) | нет | «откройте в Chrome/Safari» |
| Firefox (Android, компьютер) | да | updates.push.services.mozilla.com |
| Компьютер (Chrome/Edge/Firefox) | да, пока браузер запущен | Windows — WNS (*.notify.windows.com) у Edge |
| Яндекс Браузер и др. | не проверено | push-сервис не из списка — сервер вернёт 400, экран — «не получилось включить»; добавить хост — по факту, с проверкой |
| batr.kz/aiustaz | нет (по решению) | только aiustaz.pro |

Точность — как у карточки намаза (±1 мин к таблицам ДУМК), плюс задержка доставки push (обычно секунды). Время
отправки сервера — по UTC, цикл раз в 20 с: уведомление приходит в течение ~20 с после начала времени.

## 5. План нативной версии (Android/iOS из того же кода, после №1/№2)

- **Локальные уведомления** (expo-notifications, `scheduleNotificationAsync` по расписанию на 30 дней — тем же
  `notify/schedule.ts`): без сервера и без подписки — на сервер вообще ничего не уходит. Перепланирование при открытии
  приложения и в фоне (BackgroundFetch), iOS — до 64 запланированных, поэтому ближайшие 5–7 дней.
- **«Дуга дня»** в уведомлении: постоянное (ongoing) уведомление Android с полосой фаз дня (как «Арка дня» на главной:
  6 точек — фаджр…иша, текущая подсвечена) и обратным отсчётом до следующего; iOS — Live Activity / виджет «Следующий
  намаз». Только по выбору человека, без рейтингов и наград.
- Каналы Android: «Время намаза» (звук системный), «Напоминания заранее», «Служебные» (без звука).
- Азан кари — только запись по договору, отдельной опцией звука канала; синтеза нет.
- Web Push для сайта остаётся (у кого нет приложения).
