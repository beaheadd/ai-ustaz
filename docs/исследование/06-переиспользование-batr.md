Срезы: `beaheadd/batr-world` — коммит `021e26d` (18.11.2026), `beaheadd/batr-9qum` — коммит `be4d5fa`.
Все ссылки вида `файл:строки` относятся к этим коммитам.*

- **[Д]** — взято из внутренних документов владельца (`отделение.md`, `HANDOFF.md`, `KASPI_PAY_QR.md`, исследования mugalim 02/04/07); код не перепроверялся.

## Главное

1. **Ядро не пишем заново.** Около 1,5 тыс. строк из прода BATR и 9qum копируются как есть: `envnum`, `security`, `secretbox`, `ratelimit`, `authcodes`, `phonenorm`, `pgbackend`, `llm` [К].
2. **Готовый рецепт уже есть:** `bw/docs/aialem/отделение.md`. Там тот же сценарий: своё приложение, своя база, свой вход. Его 9 ловушек относятся и к mugalim. При чтении кода нашлось ещё около 20 [К].
3. **Главная опасность.** При пустом `DATABASE_URL` модули `db.py` и `pgbackend.py` сами читают `/etc/world.env` (`bw/server/db.py:27-39`, `pgbackend.py:32-42`). Mugalim на сервере BATR молча писал бы в базу BATR. Лечится стражем в `boot.py` и удалением этого чтения [К].
4. **Вход 4 способами.** Транспорт кодов берём: `wacloud`, `mailer`, `authcodes`, `phoneauth`/`emailauth`. Модуль аккаунтов пишем заново, около 300 строк по тем же шаблонам. В `accounts.py` BATR 1540 строк, и почти всё в нём про соцсеть BATR [К/О].
5. **Google и Apple в BATR не отдают `sub`, только почту.** Скрытую почту Apple BATR отклоняет (`bw/server/appleauth.py:68-93`). Чтобы связывать способы входа по паре `(provider, sub)`, эти модули нужно доработать [К].
6. **ИИ-наставник.** Лучшая основа — «Укки» (`educat_tutor*`, около 3,6 тыс. строк). В нём уже есть подпись реплик, гостевой доступ, лимиты, жалобы, журнал с аудитом просмотров и база знаний на BM25. Промпт и медиа (Википедия, YouTube) там школьные, их заменяем. Арабских букв поиск не видит (`educat_tutor_kb.py:61`) [К].
7. **Голос.** `stt.py` (Whisper) годится только для голосовых вопросов. Проверять чтение Корана им нельзя (документ 02, п. 6). Проверка таджвида и хифза — новый сервис речи, из BATR его не взять [К/Д].
8. **Деньги.** Основа подписки: `bw/server/kaspi_qr.py` (общий: вид оплаты, атомарный захват, дозачисление), экран `9q/web/src/online/KaspiPay.jsx` и тарифы из `9q/server/subs.py`. Внутри Android-приложения цифровое продаётся только через Google Play: `bw/server/playbilling.py` и `9q/web/src/appmode.js` [К].
9. **Учёба.** Интервальное повторение уже есть в двух местах: `9q/server/learnloop.py` (1/3/7 дн.) и `bw/web/src/educat/engine/mastery.js` (2/7/21/60 дн.). На их основе делаем манзиль хифза. Публичных рейтингов и лиг поклонения не делаем (документ 04, п. 9) [К/Д].
10. **Сначала проверить `beaheadd/aialem` (ветка `init`).** По `bw/docs/HANDOFF.md:467-470` там уже отделённый каркас: свой FastAPI, база, вход 4 способами, выкатка через Actions [Д]. В этой сессии репозитория нет. Возможно, нужное там уже вычищено, и брать его надёжнее, чем из монолита.

Решения: **КАК ЕСТЬ** — копировать без правок. **АДАПТ** — копировать и править. **НОВОЕ** — писать заново по образцу. **ОБРАЗЕЦ** — взять идею или паттерн. **НЕ БРАТЬ**.
Зрелость: «прод» — работает на batr.kz или 9qum.com; «+тест» — есть свой тест.

## 3. Как переносить, по группам

### 3.1 Ядро: `boot.py`, база, секреты

**`boot.py`** импортируется первым в `main.py`, в тестах и в скриптах (рецепт: `отделение.md:143-147`):
1. Настройки берутся из окружения, а без него — из `/etc/mugalim.env`. `/etc/world.env` не читается никогда.
2. `DATA_DIR` = `MUGALIM_DATA_DIR`. По умолчанию для разработки — `server/data` своего репозитория (папка в `.gitignore`).
3. Запуск отменяется, если база по имени или адресу совпадает с `world`, `aialem` или `toguz` либо равна `DATABASE_URL` из `/etc/world.env`.
4. Запуск отменяется, если `DATA_DIR` лежит внутри `/opt/world`, `/opt/aialem` или `/opt/9kumalak`.
5. Секрет токенов — свой, в `<DATA_DIR>/secret.key`, права 600. Токен batr.kz для mugalim недействителен, и наоборот.

**`db.py`** — новый и тонкий. Он сохраняет API, от которого зависит копируемый код: `conn()`, `lock()`, `get_meta`, `set_meta`, `ensure_tables`, `ensure_columns`, `close_conn`, `IntegrityError`, `USE_PG`, `DATA_DIR`. Схема хранится не в нём: каждый модуль создаёт свои таблицы сам (`CREATE TABLE IF NOT EXISTS`), как `ratelimit` и `authcodes`. Ядро — `schema.py`. SQLite остаётся для тестов и разработки, PostgreSQL — для прода.

**Замок.** В bw замок PG реентерабельный (`pgbackend.py`, RLock), в 9q — `_GuardLock`, который падает при повторном входе. Для денежных функций берём подход 9q: функции `*_tx(c, …)` принимают уже открытое соединение, а тест проверяет, что вложенных замков нет (как `9q/server/__tests__/test_no_nested_lock.py`) [К].

**`secretbox`** — самописная схема: поток HMAC-SHA256 в режиме счётчика плюс тег, метки `box-ks` и `box-tag` разделяют ключи. Для хранения ключей в покое она приемлема [О]. На старте нового проекта дешевле взять AES-GCM из `cryptography`: библиотека и так приходит с PyJWT[crypto] и pywebpush. Ключ стоит выводить из секрета с меткой «secretbox» [О]. Решение не критично, можно копировать как есть.

### 3.2 Вход: 4 способа

```
POST /api/auth/code   {channel: phone|email, to}
  → codeauth.запросить(): нормализация (phonenorm / lower)
  → authcodes.reserve("p:<номер>" | "e:<почта>", gap, per_hour) и reserve("pip:<ip>")   ← атомарный клейм
  → authcodes.store(ident, код из 6 цифр, 600 с)
  → ПровайдерКода.отправить(адрес, код, язык)   ← WhatsAppCloud | МостBATR | Smtp | Заглушка (тесты)
       сбой → authcodes.unreserve(...): кулдаун не засчитан
POST /api/auth/verify {channel, to, code} → authcodes.verify(5 попыток) → accounts.по_контакту(подтверждённому)
POST /api/auth/google {credential} | /api/auth/apple {id_token} → (sub, почта, подтверждена) → auth_ids(provider, sub)
→ {token: security.make_token(логин, token_ver), user, created}
```

- **Сопоставление аккаунта** — только по подтверждённым телефону или почте и по `(provider, sub)` (`отделение.md:214-216`). Шаблон защиты от двойного создания на мультиворкере — `bw/server/accounts.py:933-980`: проверка и вставка в одной секции, частичный UNIQUE, повторное чтение при `IntegrityError` [К].
- **Логин не из цифр телефона.** Публичный ник «user123456» случайный, иначе по нему восстанавливается номер (`accounts.py:952-954`) [К].
- **Google.** `tokeninfo` — это сетевой запрос на каждый вход. Google советует его для отладки, а в проде — проверять подпись по своим JWKS (не проверено). У нас уже есть PyJWT (`appleauth`), так что `googleauth.py` устроен так же, как `appleauth.py`.
- **Apple.** Нужно отдавать `sub`. Скрытую почту принимать как подтверждённую, но по ней не сопоставлять. При удалении аккаунта нужен отзыв токена: ключ .p8, Key ID, Team ID (`отделение.md:255-256`) [Д].
- **Россия.** Коды через WhatsApp там фактически не доходят (документ 04, п. 7) [Д]. Для РФ позже понадобятся почта или SMS. Интерфейс `ПровайдерКода` это уже допускает.
- **Резервное SMS** — только по флагу, как `WORLD_SMS_FALLBACK` в BATR (`bw/server/app.py:115-131`) [К].
