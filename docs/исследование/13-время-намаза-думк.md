# 13. Время намаза по ДУМК и кибла — что известно (19.11.2026)

## Главное

> **Решение владельца 20.11.2026:** «Время намаза Казахстан, Узбекистан бери из официальных источников… чтобы с местными
> один в один у нас время было. А остальные по такой методологии можно считать» (и спросил, можно ли брать через API).
> Это решение заменяет прежнюю оговорку «без письменного разрешения ДУМК в продукте не используем» (п. 1 ниже). Письмо в
> ДУМК о разрешении остаётся в силе и идёт параллельно. Подпись в приложении — «По данным ДУМК». Как сделано — раздел
> «Официальные таблицы ДУМК в продукте (20.11.2026)» в конце.
>
> 20.11.2026: Узбекистан и весь мир (метод по стране места, без выбора страны) — исследование 15
> (`15-время-намаза-мир.md`). Метод ДУМК для РК не менялся.
1. **У ДУМК есть API, которым пользуется их сайт muftyat.kz.**
   - Расписание: `https://api.muftyat.kz/prayer-times/<год>/<широта>/<долгота>`.
   - Список населённых пунктов: `https://api.muftyat.kz/cities/` — около 5 700 мест.
   - На GitHub его используют больше 30 проектов. Публичной документации и условий использования нет: это внутренний API сайта.
   - ~~Поэтому без письменного разрешения ДУМК в продукте его не используем.~~ — прежняя позиция; заменена решением
     владельца 20.11.2026 (выше): берём таблицы через этот API, письмо в ДУМК — параллельно.
2. **Метод ДУМК восстановлен по их таблицам** (сторонний открытый проект, сверка с ответами API за октябрь–ноябрь 2026):
   - расчёт как в praytimes.js, метод ISNA: фаджр и иша — 15°;
   - аср — по ханафитскому мазхабу;
   - высокие широты — правило AngleBased;
   - поправки: восход −3 мин, зухр, аср и магриб +3 мин южнее 48° с. ш.; −5 и +5 мин на 48° с. ш. и севернее (магриб = закат + 3 или + 5 мин);
   - поле `imsak` = фаджр + 10 мин в расчётах не используется: начало поста — по фаджру.
3. **Точность своего расчёта этим методом против таблиц ДУМК:**
   - юг (Алматы и др.) — расхождение до 1 минуты;
   - Астана — фаджр и иша до 5–6 минут;
   - Петропавловск и дальний север — фаджр до 8 минут, иша до 6 минут, весной и летом.

   Вывод: свой расчёт годится как запасной и для «тихих окон» уведомлений, но **время для показа людям — только из данных ДУМК**. Ошибка в 5–8 минут на фаджре и в конце сухура недопустима.

   > *Прежняя позиция — до сверки 19.11.2026. Сверка ниже её отменила: расхождение ≤ 1 мин, приложение показывает свой расчёт (см. «Обновление 19.11.2026» в конце).*
4. **Особенности API:**
   - отвечает только на координаты своих мест из `/cities/`;
   - пять мест с одинаковыми координатами отдают ошибку 500;
   - бывают разовые несогласованные ответы (Жезказган, 09.11.2026), поэтому принимаем таблицу только после проверки правила полос и повторного запроса.

## Сверка 19.11.2026: наш расчёт против таблиц ДУМК — совпадает
Доступ к api.muftyat.kz владелец разрешил 19.11.2026. Скрипт — `tools/prayer/compare_dumk.py`.

**Наш расчёт:** adhanpy (MIT), метод выше: ISNA 15°/15°, аср ханафи, TwilightAngle, поправки ±3/±5, UTC+5.

**Результат за все 365 дней 2026 года, все шесть времён:**
- **23 города из 24 — расхождение не больше 1 минуты.** Это:
  - юг — Алматы, Шымкент, Туркестан, Тараз, Сарыагаш, Жаркент, Талдыкорган;
  - запад — Актау, Атырау, Актобе, Уральск;
  - центр — Астана, Караганда, Жезказган, Балхаш, Арал, Байконур;
  - север и восток — Костанай, Кокшетау, Павлодар, Экибастуз, Петропавловск, Семей, Усть-Каменогорск, Риддер.

  Север летом тоже в пределах 1 минуты. Сторонний отчёт с расхождением до 8 минут не подтвердился. Отдельные дни дают 2 минуты: Актобе, Уральск, Петропавловск — по одному времени в году.
- Минута в минуту совпадают 82–91% значений. Остальное — округление на 1 минуту.
- **Кызылорда — до 3 минут, в пределах минуты только 52%.** Причину нужно разобрать: другие координаты в таблицах ДУМК или своя поправка. До разбора в Кызылорде и области показываем только таблицы ДУМК.

  > *Прежняя позиция. Повторная сверка 19.11.2026: Кызылорда ≤ 1 мин, «до 3 мин» был разовый сбой ответа API (см. «Обновление 19.11.2026»).*
- Зайсан — не найден в списке мест ДУМК под этим названием.

**Вывод:**
- Свой расчёт можно использовать как надёжный запасной вариант: без сети, для мест вне списка и для «тихих окон».
- Подпись «по данным ДУМК» — только когда показываем их таблицу (после разрешения).
- Для своего расчёта подпись «расчёт по методу ДУМК, сверено с их таблицами (±1 мин)».
- Сверку повторять каждый год (январь) и после любых объявлений ДУМК.

## План
1. **Письмо в ДУМК (владелец).** Просим разрешения брать официальное расписание (годовые таблицы по населённым пунктам) для бесплатного приложения AI Ustaz без рекламы, с подписью «по данным ДУМК». Хорошо бы в том же меморандуме, что и проверка курса (ПЛАН §9).
2. **Сервер AI Ustaz (свой домен, РК):**
   - раз в год и по требованию скачивает таблицы на текущий и следующий год для всех мест;
   - проверяет их;
   - хранит в своей БД и отдаёт приложению город и год целиком, чтобы всё работало офлайн.

   Координаты пользователя на сервер не уходят: выбор ближайшего места — на телефоне по списку мест.
3. **Приложение:**
   - экран «Время намаза»: город, пять времён, обратный отсчёт, «урок после намаза»;
   - кибла — направление по формуле большого круга, стрелка на карте; компас — «как получится» в вебе, точный — в Android.
4. **Свой расчёт** (adhan-js, MIT) этим методом — только для «тихих окон» уведомлений и как запасной, когда нет сети и нет загруженной таблицы. Тогда пометка «расчёт, может расходиться с ДУМК на несколько минут». На севере летом не показываем вовсе.
5. **Проверка:** сверка с таблицами ДУМК по 20–30 городам за год; расхождение данных из API — 0 минут, своего расчёта — по таблице выше.

## Официальные таблицы ДУМК в продукте (20.11.2026)

Решение владельца 20.11.2026 — в «Главном». Сделано (ветка `ccr-2a2e1f47-0y7nhw`):

1. **Сервер** (`server/prayer.py`, миграция 003): служба `mugalim-jobs` (отдельный поток) скачивает годовые таблицы
   `https://api.muftyat.kz/prayer-times/<год>/<широта>/<долгота>` для 168 мест приложения. Каждому месту сопоставлен
   пункт ДУМК (`server/prayer_places.json`, `tools/prayer/build_server_places.py`: то же имя, «… қаласы» предпочтительнее,
   Индербор → «Индер»; координаты — точные строки из `/cities/`). Таблица принимается, если **два ответа подряд
   совпали** (против разовых сбоев, как Жезказган 09.11 и Кызылорда 19.11), в ней 365/366 дней подряд, 6 времён «ЧЧ:ММ»
   по порядку и **расхождение со своим расчётом методом ДУМК ≤ 10 мин** (иначе — отказ, журнал `prayer_log`, повтор через
   час; принятая раньше таблица остаётся). Перепроверка — раз в 7 дней, с 1 ноября — таблица следующего года. Отдаёт
   `GET /api/prayer/official?src=dumk&place=<id>&year=<год>` (только из своей БД, ETag, кэш сутки).
2. **Телефон** (aiustaz.pro): для мест РК (и своей точки, если ближайшее место списка ≤ 25 км) берёт таблицу года по
   **id места** — координаты не уходят; хранит её у себя (localStorage), повторно не качает (перепроверка раз в неделю
   с If-None-Match → 304). Подпись — «По данным ДУМК · обновлено ДД.ММ.ГГГГ». Без сети, на batr.kz, пока сервер не
   скачал, и при шафиитском асре — свой расчёт с подписью «Расчёт по методу ДУМК (±1 мин)». Уведомления строятся из
   той же таблицы.
3. **Пять пунктов без таблицы** — у ДУМК по две записи с одной точкой (Есік қаласы и Есік; Абай қаласы и Дуаншы;
   Щучинск, Жітіқара, Тобыл), API на них отвечает 500 (тот самый «500 на пять мест» из п. 4 «Особенности»). Помечены
   «дубль»: сервер их не спрашивает, API отвечает `404 no_official`, телефон считает сам (≤ 1 мин). Если ДУМК исправит
   дубли — пересобрать `prayer_places.json` скриптом.
4. **Живая проверка 20.11.2026** (сам код сервера `prayer.таблица_думк` против api.muftyat.kz, запросы по одному с
   паузой): **2026 год — 163 из 168 мест приняты** (два одинаковых ответа подряд, проверка пройдена), 5 — «дубль» (500);
   2027 год — 10 из 10 (Алматы, Астана, Шымкент, Петропавл, Ақтау, Қызылорда, Өскемен, Қостанай, Жезқазған, Орал).
   Каждая принятая таблица со своим расчётом по точке ДУМК — ≤ 1 мин. Свой расчёт по точкам приложения (GeoNames)
   против всех 163 таблиц: 356 970 значений, минута в минуту 86,4 %, 1 мин — 48 486, 2 мин — 22 (Ботакара, Жымпиты),
   больше — нет. Полный цикл «телефон спросил → 404 not_ready → jobs скачал → 200 → 304» прогнан на временной базе.
   16 городов (Алматы, Астана, Шымкент, Караганда, Актобе, Тараз, Павлодар, Өскемен, Семей, Атырау, Костанай,
   Кызылорда, Орал, Петропавл, Актау, Туркестан) — фикстура `app/scripts/fixtures/prayer-official-tables.json`: показываемое время = таблица ДУМК
   во все 365 дней × 6 (0 мин); свой расчёт по точке приложения (GeoNames) — ≤ 1 мин, минута в минуту 71,6–89,5 %.
5. **Риски.** API — внутренний API сайта muftyat.kz без документации и условий: может смениться форма ответа, адрес или
   включиться защита. Тогда проверка формы не пропустит новые таблицы, приложение покажет последнюю принятую (до конца
   года) или свой расчёт — время не пропадёт. Нагрузка на ДУМК — 163 таблицы × 2 запроса в год + перепроверка раз в
   неделю (≈ 50 запросов в день), с паузой 2 с. Письмо в ДУМК — просим разрешение и, если можно, адрес выгрузки.
6. **Сети:** серверу BATR нужен выход к `api.muftyat.kz:443` (служба `mugalim-jobs`); из облачной сессии он открыт.
