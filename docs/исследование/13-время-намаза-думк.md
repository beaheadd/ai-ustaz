# 13. Время намаза по ДУМК и кибла — что известно (19.11.2026)

## Главное
1. **У ДУМК есть API, которым пользуется их сайт muftyat.kz.**
   - Расписание: `https://api.muftyat.kz/prayer-times/<год>/<широта>/<долгота>`.
   - Список населённых пунктов: `https://api.muftyat.kz/cities/` — около 5 700 мест.
   - На GitHub его используют больше 30 проектов. Публичной документации и условий использования нет: это внутренний API сайта.
   - **Поэтому без письменного разрешения ДУМК в продукте его не используем.**
2. **Метод ДУМК восстановлен по их таблицам** (сторонний открытый проект, сверка с ответами API за октябрь–ноябрь 2026):
   - расчёт как в praytimes.js, метод ISNA: фаджр и иша — 15°;
   - аср — по ханафитскому мазхабу;
   - высокие широты — правило AngleBased;
   - поправки: восход −3 мин, зухр, аср и магриб +3 мин южнее 48° с. ш.; −5 и +5 мин на 48° с. ш. и севернее (магриб = закат + 3 или + 5 мин);
   - поле `imsak` = фаджр + 10 мин в расчётах не используется: начало поста — по фаджру.
3. **Точность своего расчёта этим методом против таблиц ДУМК:**
   - юг (Алматы и др.) — расхождение до 1 минуты;
   - Астана — фаджр и иша до 5–6 минут;
   - Петропавловск и дальний север — фаджр до 8 минут, иша до 6 минут, весной и летом.

   Вывод: свой расчёт годится как запасной и для «тихих окон» уведомлений, но **время для показа людям — только из данных ДУМК**. Ошибка в 5–8 минут на фаджре и в конце сухура недопустима.
4. **Особенности API:**
   - отвечает только на координаты своих мест из `/cities/`;
   - пять мест с одинаковыми координатами отдают ошибку 500;
   - бывают разовые несогласованные ответы (Жезказган, 09.11.2026), поэтому принимаем таблицу только после проверки правила полос и повторного запроса.

## Сверка 19.11.2026: наш расчёт против таблиц ДУМК — совпадает
Доступ к api.muftyat.kz владелец разрешил 19.11.2026. Скрипт — `tools/prayer/compare_dumk.py`.

**Наш расчёт:** adhanpy (MIT), метод выше: ISNA 15°/15°, аср ханафи, TwilightAngle, поправки ±3/±5, UTC+5.

**Результат за все 365 дней 2026 года, все шесть времён:**
- **23 города из 24 — расхождение не больше 1 минуты.** Это:
  - юг — Алматы, Шымкент, Туркестан, Тараз, Сарыагаш, Жаркент, Талдыкорган;
  - запад — Актау, Атырау, Актобе, Уральск;
  - центр — Астана, Караганда, Жезказган, Балхаш, Арал, Байконур;
  - север и восток — Костанай, Кокшетау, Павлодар, Экибастуз, Петропавловск, Семей, Усть-Каменогорск, Риддер.

  Север летом тоже в пределах 1 минуты. Сторонний отчёт с расхождением до 8 минут не подтвердился. Отдельные дни дают 2 минуты: Актобе, Уральск, Петропавловск — по одному времени в году.
- Минута в минуту совпадают 82–91% значений. Остальное — округление на 1 минуту.
- **Кызылорда — до 3 минут, в пределах минуты только 52%.** Причину нужно разобрать: другие координаты в таблицах ДУМК или своя поправка. До разбора в Кызылорде и области показываем только таблицы ДУМК.
- Зайсан — не найден в списке мест ДУМК под этим названием.

**Вывод:**
- Свой расчёт можно использовать как надёжный запасной вариант: без сети, для мест вне списка и для «тихих окон».
- Подпись «по данным ДУМК» — только когда показываем их таблицу (после разрешения).
- Для своего расчёта подпись «расчёт по методу ДУМК, сверено с их таблицами (±1 мин)».
- Сверку повторять каждый год (январь) и после любых объявлений ДУМК.

## План
1. **Письмо в ДУМК (владелец).** Просим разрешения брать официальное расписание (годовые таблицы по населённым пунктам) для бесплатного приложения AI Ustaz без рекламы, с подписью «по данным ДУМК». Хорошо бы в том же меморандуме, что и проверка курса (ПЛАН §9).
2. **Сервер AI Ustaz (свой домен, РК):**
   - раз в год и по требованию скачивает таблицы на текущий и следующий год для всех мест;
   - проверяет их;
   - хранит в своей БД и отдаёт приложению город и год целиком, чтобы всё работало офлайн.

   Координаты пользователя на сервер не уходят: выбор ближайшего места — на телефоне по списку мест.
3. **Приложение:**
   - экран «Время намаза»: город, пять времён, обратный отсчёт, «урок после намаза»;
   - кибла — направление по формуле большого круга, стрелка на карте; компас — «как получится» в вебе, точный — в Android.
4. **Свой расчёт** (adhan-js, MIT) этим методом — только для «тихих окон» уведомлений и как запасной, когда нет сети и нет загруженной таблицы. Тогда пометка «расчёт, может расходиться с ДУМК на несколько минут». На севере летом не показываем вовсе.
5. **Проверка:** сверка с таблицами ДУМК по 20–30 городам за год; расхождение данных из API — 0 минут, своего расчёта — по таблице выше.
