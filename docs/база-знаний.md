# База знаний «Спросить AI Ustaz» — что готовить и как загружать

Владелец 20.11.2026: «Мы загрузим базу знаний, хадисы, Коран, тафсиры … например, по закяту … Только с нашей базы
данных, в интернете не будет искать, только с нашей базы данных, чтобы достоверная информация была.»

«Спросить AI Ustaz» отвечает **только** записями этой базы. Чего в базе нет — того в ответе нет («В нашей базе пока нет
ответа»). Поэтому качество ответов = качество и полнота базы. Дизайн функции — `docs/дизайн/08-спросить-устаза.md`.

## 1. Кто готовит и кто проверяет (CLAUDE.md, правило 11)

| Шаг | Кто | Что |
|---|---|---|
| Подготовка | редактор (владелец назначает) | собирает записи из **изданных** источников (ДУМК, проверенные сборники хадисов, изданный тафсир, утверждённые переводы смыслов), пишет файл JSONL, ставит `"статус": "черновик"` |
| Проверка | устаз (сейчас — знакомый устаз или кари из братьев; совет и ДУМК — когда вырастем) | читает каждую запись; утверждённой ставит `"статус": "утверждено"`, `"кто_проверил"`, `"когда"` |
| Казахский и узбекский | редактор-носитель языка, словарь терминов ДУМК | тексты kk/uz — черновик, пока их не проверили |
| Загрузка | ведущий или владелец на сервере | `python -m kb_load <файл>` (раздел 4) |

Пока запись не утверждена, в ответе у неё `черновик: true`, и приложение показывает плашку «черновик». Черновые записи
попадают в ответы только при `MUGALIM_ASK_DRAFTS=1` (по умолчанию — да, на время запуска среди своих).

Не готовим и не загружаем: фетвы на личные случаи, ИИ-тафсир, сгенерированные тексты, хадисы без оценки, тексты
с политикой, течениями и спорами мазхабов. Данные под некоммерческими лицензиями и данные Quran Foundation — только
после решения владельца о лицензии (CLAUDE.md, «Готовое — сначала»).

## 2. Формат: одна строка — одна запись (JSON, UTF-8)

```json
{"id": "zakat-nisab", "вид": "статья", "источник": "ДУМК, «…» (ссылка, дата)",
 "тексты": {"ru": {"заголовок": "Закят: нисаб и доля", "текст": "…"},
            "kk": {"заголовок": "Зекет: нисап және үлес", "текст": "…"}},
 "статус": "черновик", "версия": 1}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | латиница, цифры, `.-_`, 2–80 символов; постоянный — по нему обновляется запись |
| `вид` | да | `коран`, `хадис`, `тафсир`, `статья`, `справка` |
| `тексты` | да | `ru` обязателен (`kk`, `uz` — если есть; иначе выдаём `ru`); в каждом `заголовок` (≤ 200) и `текст` (≤ 8000). **Арабского письма в заголовках и текстах нет** (правило 1) |
| `источник` | да | издание, сборник, статья ДУМК со ссылкой и датой (≤ 300) |
| `ссылка` | по виду | `коран`, `тафсир` — «сура:аят» или «сура:аят-аят» (`2:255`, `2:255-257`) в пределах 114 сур и числа аятов; `хадис` — собирается сама: «сборник, номер» |
| `арабский` | только `хадис` | дословно из проверенной базы хадисов; у любого другого вида — отказ |
| `сборник`, `номер`, `степень`, `кто_оценил` | `хадис` — все четыре | номер — с цифрой; без любого из них хадис не загрузится (правило 2) |
| `статус` | да | `черновик` или `утверждено` |
| `кто_проверил`, `когда` | при `утверждено` | имя устаза и дата `ГГГГ-ММ-ДД` |
| `версия` | да | целое ≥ 1; поднимать при любом изменении содержания |

Лишние поля — отказ (чтобы опечатка в имени поля не проходила молча).

### По видам

- **`коран`** — арабский текст аята в базе **не храним** (правило 1): приложение показывает аят само из проверенной
  копии Tanzil Uthmani v1.1 по ссылке «сура:аят». В записи — ссылка, заголовок и, если есть, **перевод смыслов** в
  `текст` с изданием в `источник` («Перевод смыслов …, издатель, год»). Текст может быть пустым — тогда это только ссылка.
- **`хадис`** — только из проверенной базы: `сборник` («Сахих аль-Бухари»), `номер` («1»), `степень` («сахих»),
  `кто_оценил` (кто дал степень), `арабский` — дословно, перевод — проверенный. ИИ хадисы не пишет и не пересказывает.
- **`тафсир`** — только из **изданного** тафсира, с `ссылка` на аят и изданием в `источник`. Показывается как есть,
  когда спрашивают тафсир этого аята; ИИ его не пересказывает (правило 5: ИИ-тафсира нет).
- **`статья`** — материалы ДУМК и утверждённые тексты (например, закят: нисаб, доля, сроки). Общие сведения, не фетва.
- **`справка`** — о самом приложении (`content/kb/spravka.jsonl`: 11 записей ru + kk, все — черновик). Не религиозный
  контент, но тоже проверяет владелец.

## 3. Версия и хэш

Загрузчик считает **sha256 содержания** (вид, ссылка, источник, арабский, степень, кто_оценил, все тексты) сам.

- Содержание изменилось, а `версия` не выросла — **отказ всего файла**: ничего не записано.
- Та же версия и тот же хэш, но другой `статус` / `кто_проверил` — обновляется только статус (утверждение без правки).
- Версия в файле меньше, чем в базе, — отказ.
- В ответе API `версия` — «версия.первые 8 знаков sha256» (например, `3.9f2c1a0b`): видно, что именно показали.
- Записи, которых нет в файле, не удаляются (файлов может быть несколько: `spravka.jsonl`, `zakat.jsonl`, …).
  Удаление записи — пока только вручную в базе по решению владельца.

## 4. Загрузка

На сервере (из `/opt/mugalim/server`, база — `MUGALIM_DATABASE_URL`, страж `boot.py` не пустит в чужую базу):

```bash
python -m kb_load --check ../content/kb/zakat.jsonl   # только проверить файл: ошибки всех строк сразу
python -m kb_load ../content/kb/zakat.jsonl           # загрузить: всё или ничего, одной транзакцией
```

Код выхода: 0 — загружено, 1 — ошибки (ничего не записано), 2 — нет файла. Итог: «новых N, изменено M, статус обновлён K,
без изменений L». Файлы базы с религиозным контентом кладём в `content/kb/` только после проверки устазом
(или с `"статус": "черновик"`).

## 5. Как пишется запись, чтобы её нашли

Поиск — полнотекстовый PostgreSQL по заголовку (вес выше) и тексту, на языке вопроса (`russian` для ru, `simple`
для kk/uz). Запись находится, если в ней есть хотя бы ~треть значимых слов вопроса (`MUGALIM_ASK_MIN_SHARE` = 0,3).

- Заголовок — так, как люди спрашивают: «Закят: с чего платить, нисаб и доля», а не «Раздел 4.2».
- Одна запись — одна тема; длинные материалы делить на записи по 1–3 абзаца.
- Писать и казахский текст (`kk`): у kk-вопроса поиск идёт по kk-тексту, а ru — только запасной показ.
- Узбекская латиница — без разницы `o'`/`oʻ`/`o’` (апострофы выравниваются).
