# AI Ustaz — каркас приложения (контракт для агентов)

Expo SDK 58 (React Native 0.88, React 19.3, TypeScript 6) + веб-экспорт. Живёт на **batr.kz/aiustaz** как статические файлы. Честный прототип v0: на batr.kz проверки голоса ИИ нет, голоса кари нет, уроки — черновик, входа нет. Проверка голосом (речевой сервис) есть в коде, но выключена по умолчанию и работает только на своём домене — раздел «Проверка голосом».

Правила проекта — `/home/user/mugalim/CLAUDE.md` (обязательны). Здесь — только то, что нужно, чтобы писать экраны.

Экран — `function Имя({ параметры }: ПропсыЭкрана<'маршрут'>)`. Заменяя заглушку, сохраните имя файла и экспорт (или поправьте `screens/index.ts`).

```ts
const { перейти, назад, заменить, обновитьПараметры, наГлавную, перейтиВкладку, текущий, стек, можноНазад, задатьЗащиту } = useНавигация(); // engine/navigation
перейти('урок', { номер: 3 });   перейти('оПроекте');   перейти('сура', { номер: 2, аят: 255 });
обновитьПараметры('проверкаАята', { номер: 2, аят: 255, часть: 2 }); // тот же экран и ключ (без перемонтирования), новый адрес (replaceState)
перейтиВкладку('таджвид');        // раздел нижнего меню: стек [главная, корень раздела] (ссылки на другой раздел — только так)
заменить('урок0');               // без новой записи в истории (например, онбординг → урок 0)
назад();                          // как «назад» браузера
задатьЗащиту(() => { показатьДиалог(); return true; });  // перехватить «назад» браузера/системы; null — снять
```

- **Защита ухода** (`задатьЗащиту`): пока она стоит, «назад/вперёд» браузера, свайп «назад» iOS Safari и системная «назад» Android не уводят с экрана — функция защиты вызывается, и если вернула `true`, стек остаётся, а в историю снова кладётся запись текущего экрана. Урок ставит её на время заданий и показывает «Выйти из урока?»; после подтверждения сам снимает (флаг) и вызывает `назад()`. Кнопки приложения защиту не проверяют.

- Стек живёт в состоянии; на вебе каждый шаг — запись `history.pushState` с hash и полным стеком в `history.state`. «Назад/вперёд» браузера, перезагрузка и глубокая ссылка `/aiustaz#/lesson/3` работают; внизу стека всегда главная.
- **Адреса Корана** (`routes.ts`, 19.11.2026): путь из двух сегментов (`quran/sura`, `quran/check` — сопоставляется самый длинный), параметры query-строкой: только `n`, `a`, `p`, только цифры (1–3), без повторов и чужих ключей — иначе `null` (главная). `вХэш` пишет `a`/`p`, только если заданы. Глубокая ссылка — `предкиГлубокойСсылки`: `#/quran/sura?n=2&a=255` → `[главная, коран, сура]`, `#/quran/check?…` → `[главная, коран, сура у аята, проверка]`, у каждого уровня своя запись в истории («назад» идёт по ним).
- Путевой маршрутизации нет (nginx batr.kz без `$uri/`): только hash. Видимый адрес — `/aiustaz/index.html#/…` (константа `КРАСИВЫЙ_АДРЕС` в `history.web.ts` включает `/aiustaz#/…`, тогда перезагрузка идёт через редирект BATR).
- Рисуется только верхний экран: уход с экрана его размонтирует (запись голоса удаляется).
- Новый экран: маршрут в `engine/routes.ts` (`Маршруты`, `ПУТИ`, при параметрах — `ПАРАМЕТРЫ`) → файл в `screens/` → строка в `ЭКРАНЫ` → раздел в `ВКЛАДКА_ЭКРАНА` (а если у экрана свой закреплённый `низ` — в `ФОКУСНЫЕ`). Typecheck проверит полноту.

### Нижнее меню (решение владельца 19.11.2026; анализ — `docs/дизайн/04-нижнее-меню-и-главная.md`)

- **Разделы** (`engine/routes.ts`): `ВКЛАДКИ = ['главная', 'таджвид', 'коран', 'хадисы', 'ещё']`; `КОРЕНЬ_ВКЛАДКИ` — главная → `главная`, таджвид → `картаКурса` (`#/course`), коран → `коран` (`#/quran`), хадисы → `хадисы` (`#/hadith`), ещё → `ещё` (`#/more`). Подписи ru — Главная · Таджвид · Коран · Хадисы · Ещё; kk (черновик) — Басты бет · Тәжуид · Құран · Хадис · Тағы.
- **Инвариант стека:** `[главная]` или `[главная, корень раздела, …подстраницы]`. Подстраницы главной («Время намаза», «Кибла», «Город») кладутся прямо на главную.
- **Подсветка** — `активнаяВкладка(стек)`: при одном экране — главная, иначе `ВКЛАДКА_ЭКРАНА[стек[1].экран]`. Подстраница остаётся в разделе, откуда её открыли: «Город» из «Ещё» — «Ещё», с главной — «Главная»; `#/about`, `#/licenses`, `#/how` по прямой ссылке — «Ещё»; урок и урок 0 — «Таджвид».
- **`перейтиВкладку(в)`**: «главная» — как `наГлавную()`; тот же раздел с подстраницы — назад к корню раздела (`history.go`); другой раздел — `[главная, корень]` (со стека длиннее 1 — сначала `history.go(-(n-1))` до главной, затем в обработчике popstate push корня; верхнюю запись глубокого стека не заменяем). Повторное нажатие раздела на его корне — меню прокручивает экран к началу (`прокрутитьЭкранВверх()` из `components/Screen.tsx`).
- **Двойное нажатие** (ревью 19.11.2026): `history.go` асинхронен — пока не пришёл popstate, `переходИдёт` (ref в `ПоставщикНавигации`, страховка 800 мс) и `назад`, `наГлавную`, `перейтиВкладку`, `перейти`, `заменить` ничего не делают; иначе второе нажатие уводило со страницы (на batr.kz). Тест — `e2e-nav.mjs`, сценарий 9.
- **«Назад»** (Android, браузер, свайп): подстраница → корень раздела → главная → уход со страницы. В шапке корня раздела (стек длины 2) кнопки «Назад» нет — эмблема (правило в `<Экран>`). Перезагрузка и глубокая ссылка `#/quran` открывают `[главная, коран]`; адрес, поправленный вручную, — тоже как глубокая ссылка.
- **Фокусные экраны** `ФОКУСНЫЕ` = урок, урок 0, онбординг: меню скрыто (у них свой закреплённый `низ`). Правило: экран с `низ` — всегда фокусный; экраны с меню `низ` не используют.
- **Где рисуется:** `App.tsx` → `<Каркас>`: экран (flex 1), под ним `<МиниПлеер>` (чтение кари; в «стоп» его нет) и `<НижнееМеню>` — обычными элементами колонки (не `position: fixed`) — прокрутка экрана короче на их высоту, содержимое под них не уходит. На фокусных экранах нет ни меню, ни мини-плеера, а чтение кари ставится на паузу (у урока свой звук и запись). Высота 64 + `env(safe-area-inset-bottom)` на вебе; нативно — позже `react-native-safe-area-context` (и скрывать меню при открытой клавиатуре).
- **Доступность:** веб — `<nav aria-label="Основные разделы">`, пункты — `<a href="#/…">` (клик перехвачен: `preventDefault` + `перейтиВкладку`), у активного `aria-current="page"`, Tab/Enter, кольцо `:focus-visible` внутри пункта (`data-focus="inside"`, offset −3 px); нативно — `tabbar`/`tab` + `accessibilityState.selected`. Значки декоративные. Подпись не шире пункта: при крупном тексте и масштабе 200 % слово переносится (`overflow-wrap: anywhere`, `hyphens: auto`), меню растёт, но подписи не налезают.
- **Состояния для диктора на вебе — только `aria-*`:** react-native-web 0.21 не переносит `accessibilityState` в DOM. Поэтому `aria-checked` (язык, тема — `<Вкладки роль="выбор">` = radiogroup/radio, выбор в уроке 0), `aria-selected` (вкладки урока), `aria-expanded` (раскрывашки, этапы карты), `aria-pressed` (выбранный вариант/строка), `aria-disabled`. Новые компоненты — так же.
- **Экран и фокус (`<Экран>`):** содержимое — ориентир `main`; заголовок экрана — h1 (`уровень={1}`, `tabIndex −1`); если при смене экрана фокус пропал (на body), он переходит на заголовок нового экрана (без кольца, `data-focus="heading"`; при загрузке страницы не двигаем). Заголовки разделов внутри экранов — `<Текст … уровень={2}>`. Цели касания ≥ 48 px («Назад», сегменты языка и темы).
- **Без сети:** `useДанные(имя)` → `{ состояние: 'нет', нетСвязи: true, повторить }` — чанк не загрузился (неудача не кэшируется, «Повторить» работает без перезагрузки); `нетСвязи: false` — файл не прошёл проверку. Главная в простое подгружает урок 0 (ИИ-предупреждение), аль-Фатиху («Как объясняем») и индекс сур (вкладка «Коран»). «Лицензии» — «Нет связи» и «Повторить».
- **testID:** `нижнее-меню`, `меню-главная`, `меню-таджвид`, `меню-коран`, `меню-хадисы`, `меню-ещё`. Тест — `scripts/e2e-nav.mjs`.

- Шрифты: интерфейс — Inter 400/600 (`ШРИФТ_ИНТЕРФЕЙСА`; на вебе стек «Inter, System», `font-display: swap`, `<link rel="preload">` на оба woff2 ставит `after-export`), арабский — Amiri Quran (`ШРИФТ_АРАБСКИЙ`). ## Проверка голосом (только свой домен, выключена по умолчанию)

Решение владельца и лицензия QML: проверка моделью `quran-muaalem` — **только на своём домене AI Ustaz, никогда на batr.kz**.

- **Включение** (`speech/flag.ts`, `проверкаГолосомВключена()`): (а) сборка с `EXPO_PUBLIC_SPEECH_CHECK=1` — Expo вшивает `process.env.EXPO_PUBLIC_*` в бандл при `expo export`; (б) `location.hostname` не `batr.kz` и не `*.batr.kz` — на batr.kz всегда выключено, даже если туда выложат сборку с флагом; локально (`localhost`, `127.0.0.1`) — при том же флаге. Чистая часть — `проверкаРазрешенаДля(хост, флаг)`.
  ```
  npm run build:web                                                         # batr.kz: проверка выключена (по умолчанию)
  EXPO_PUBLIC_SPEECH_CHECK=1 MUGALIM_TARGET=own-domain npm run build:web    # свой домен: проверка включена
  EXPO_PUBLIC_SPEECH_CHECK=1 npx expo start --web                           # localhost: кнопка есть; /api/speech дев-сервер не проксирует —
                                                                            # для живого сервиса нужен nginx перед сборкой (как на своём домене)
  ```
  `after-export` ставит в index.html метку `<meta name="aiustaz-speech-check" content="on|off">`; `check-dist` не пропускает «on» без `MUGALIM_TARGET=own-domain`.
- **Клиент** (`speech/check.ts`): `проверитьЧтение(запись, эталон, виды?, { сигнал?, текстПоказа? })` → `ИтогПроверки` (`speech/answer.ts`): `{ вид: 'ответ', замечания }` | `{ вид: 'плохой-звук', причина }` | `{ вид: 'ошибка', ошибка: 'нет-сети' | 'занят' | 'таймаут' | 'запись' | 'большая' | 'недоступно' | 'отменено' }`. Исключений не бросает. Эталон — `{ текст }` (учебный слог/слово) или `{ сура, аят, словоС?, слов? }`; `эталонЗадания(задание.читать)` строит его из данных урока. `виды` (поле `kinds`) — из `задание.виды`, если есть (сейчас в данных нет — не передаём).
  - Адрес — **относительный** `POST /api/speech/v1/proverka` (CSP `connect-src 'self'`); multipart `audio` (WAV), `text` или `sura`+`aya`(+`word_from`,`words`), `kinds`. Таймаут 20 с; 503 — «сервис занят»; запись длиннее 20 с не отправляем («плохой звук: длинно»). Без cookie и Referer.
  - WAV (`speech/wav.web.ts`): Blob MediaRecorder → `decodeAudioData` в `OfflineAudioContext(1, 1, 16000)` (браузер сам пересчитывает частоту в 16 кГц) → моно → PCM16 (`speech/wavEncode.ts`, чистые функции). Нативно — заглушка.
- **Ответ → экран** (`answer.ts`, `hints.ts`): уровни только «Проверьте себя» и «Подсказка» (любой иной уровень, в т.ч. будущая «ошибка», показывается как «Проверьте себя»); фонемы на экран не попадают; фрагмент — только если он ровно `эталон.текст[нач:кон]` ответа **и** дословно есть в тексте на экране (учебный текст или аят из Tanzil), иначе «в одном месте»; не больше 3 замечаний. Тексты — детерминированные шаблоны по коду/виду (каталог ошибок §10: мадд со счётами, S5 «Тайиба» для мунфасиля на 2, калькаля, гунна, идгам, огласовка, буква), ru + kk; **статус — черновик** (проверяет устаз; потом — в `/content` через генератор). Нет замечаний — «Мы не услышали расхождений. Проверка ИИ может ошибаться» (без «Верно»). Плохой звук — «Плохо слышно: … Это не ошибка — запишите ещё раз».
- **UI** (`<ПроверкаГолосом>` в `ПанельЗаписи` — упражнения «скажи вслух», «лестница», урок 0): после записи — «Проверить»; перед первой отправкой — «Запись уйдёт на сервер AI Ustaz в Казахстане и будет удалена сразу после проверки» (+ ИИ-предупреждение QML, если ещё не показано); согласие — `согласиеПроверкиГолосом` в прогрессе (локально). Рядом всегда «Проверка ИИ — может ошибаться, не заменяет устаза». Новая запись/удаление/уход — итог сбрасывается, незаконченный запрос отменяется. - **Конкретные подсказки** (владелец 20.11.2026: «говорить, какая буква, где неправильно произнесли»). Сервис к каждому замечанию отдаёт слог/слово (с 1), номер чтения при ×2/×3 (позиции — в ОДНОКРАТНОМ тексте), букву `{знак, id}` (id — `content/letters.json`), огласовку `{id}` (`content/harakat.json`), место вставки и звуки «ожидалось/услышано» описанием (`speech/README.md`). `answer.ts` пропускает только знакомые значения (таблицы `БУКВЫ`, `ОГЛАСОВКИ`; слог — только дословно с экрана; для аята слог не берётся) и считает `диапазон` — где подсветить в тексте показа (карта `картаНормализации`: сервис получает текст без запятых). `hints.ts` (черновик 0.2): «Проверьте себя: во втором чтении, во втором слоге «إِ» (кясра — краткое „и“) прозвучал лишний звук после гласного. ## Контент (`src/content/types.ts`, данные — `/content/*.json`)

- `Урок { номер, id, уровень, название, цель, новое, задания: Задание[], критерий: { доляВерных: 0.8 }, версия, статус, утверждено, примечание? }`.
- `Задание` (у всех есть `id`, например `'L03-07'`):
  - `теория` — карточка (`заголовок`, `текст`, `примеры?`, `буква?`);
  - `знакомство` — буква: `знак`, `название`, `формы` (с татвилем ـ; у хамзы `null`), `соединяетсяСлева`, `подсказка` (каталог §8 или `null`), `подмены[]`, `примеры`. Не оценивается;
  - `выбор` — тап, один верный; `вид?`: `буква | слог | огласовка | собери | пара | форма | вСлове | соединение` (только оформление); варианты — буквы/слоги/учебные слова или текст; `пояснение?` после ответа. **Две попытки, в долю урока идёт первая** (`components/exercises/useChoice.ts`): первая ошибка — «Посмотрите ещё раз», верный не раскрывается, «Далее» закрыто; верный ответ или вторая ошибка — задание завершено, верный подсвечен, «Далее» открыто. Арабские варианты в обратной связи — карточками «Ваш выбор» / «Нужно» крупным шрифтом;
  - `прочитай` — `строки: [{ арабский, транскрипция }]` строкой справа налево с переносом; транскрипция под каждым слогом, скрыта и открывается по нажатию. Задание готово сразу, нижняя кнопка — «Прочитал(а) — дальше». Не оценивается;
  - `запись` — читать учебный текст (`читать.учебный`) или `ФрагментКорана`, без вердикта;
  - `лестница` — ступени слог → слово, каждую записать себя; пока ступень не последняя, нижняя кнопка — «Следующая ступень».
- **Контракт упражнения** (`components/exercises/common.tsx`): `{ задание, приГотово(итог, { сразуДалее? }), заменитьДалее?(замена | null) }`. `заменитьДалее({ надпись, приНажатии?, testID? })` меняет нижнюю кнопку экрана урока (только надпись — кнопка по-прежнему ведёт дальше; с `приНажатии` — своё действие); сбрасывается при переходе к следующему заданию. Обратная связь (`ОбратнаяСвязь`) сама прокручивает экран к себе.
- Урок пройден: доля верных в `выбор` ≥ `критерий.доляВерных` (0,8). `теория`, `знакомство`, `прочитай`, `запись`, `лестница` в долю не входят.
- `ФрагментКорана { сура, аят, текст, слова?, источник: 'tanzil-uthmani-1.1', файл? /*имя XML Tanzil*/, хеш /*sha256*/ }` — текст только программно из Tanzil Uthmani v1.1, дословно. Неверный вариант аята не показывать никогда.
- `ГолосКари` в заданиях прототипа всегда `null`; клипы кари живут в `media.json` (`аудио`) и подставляются в упражнения по тексту (раздел «Материалы урока»). Синтез арабских звуков запрещён.
- `ЛокализованныйТекст = { ru, kk }`; `СтатусКонтента = 'черновик' | 'проверен-устазом' | 'подписан-советом'`.
- **Нет сети:** `загрузитьУрок` отклоняется, если чанк урока не загрузился; экран урока тогда — «Нет связи: урок не загрузился» и «Повторить» (`урок-нет-связи`, `урок-повторить`), а не «Урок не найден». Главная заранее подгружает следующий урок.
- Файлы `/content`: `media.json` (`МедиаДанные` — видео и аудио партнёров, раздел «Материалы урока»), `course.json` (`КартаКурсаДанные`: уровни 0–4 → пункты с `метка`, `вид`, `очередь`, `доступен`, `файл`), `lesson0.json` (`Урок0Данные`: `предупреждениеИИ` ar/ru/kk, `маршрут`, `намерение` — не сохранять, `задания`), `lessons/level1/L01…L16.json`, `K1.json` (`Урок`), `letters.json` (`БукваДанные[]`), `harakat.json` (`ЗнакДанные[]`), `fatiha-demo.json` (`ДемоФатихи`: аяты 1:1–7 из Tanzil + 7 примеров объяснений, слово — по номеру с 1), `sources.json`, `version.json`.
- Номера в маршруте `#/lesson/N`: 1–16 — уроки, **К1 = 101** (К2 = 102, К3 = 103, Итог = 104, Н1–Н4 = 111–114 — пока недоступны). Урок 0 — свой экран `урок0`.
- **Загрузка — лениво, отдельными чанками с хэшем.** Реестр `src/content/registry.ts` — фасад: `загрузитьКурс()`, `пунктКурса(курс, номер)`, `естьУрок(номер)`, `загрузитьУрок(номер)` (1–16, 101), `загрузитьУрок0()`, `загрузитьДемоФатихи()`, `загрузитьБуквы()`, `загрузитьЗнаки()`. Реализация одна: уроки — `engine/lessonEngine.ts` (`require.context` по `/content/lessons`, проверка формы и sha256 аятов), остальные файлы — `components/info/data.ts` (`useДанные`, `загрузитьДанные`). Статический `import` JSON из `/content` в экраны не делать: данные раздувают основной бандл (урок — 7–15 КБ, gzip 2–3 КБ). Временных фикстур уроков больше нет (`screens/__fixtures__` удалена 18.11.2026).

Tanzil по умолчанию — копия ДЛЯ ПОКАЗА в репозитории `content/quran/quran-uthmani-marks.xml` (со знаками; с 19.11.2026); цитаты слов каталога (по фонетической копии, с татвилем) сопоставляются со словом Tanzil без учёта татвиля, в текст идёт слово дословно из копии для показа. Поправки к подсказкам каталога §8 (ب, د, غ) — `ПОПРАВКИ_ПОДСКАЗОК` в генераторе, до переноса в каталог. Путь к XML Tanzil: `--tanzil ПУТЬ` или `MUGALIM_TANZIL_XML`.

## Правила (коротко)

- **Никаких растровых файлов** (png/jpg/jpeg/webp/gif/ico/bmp): иконки — SVG, текст, эмодзи без лиц. Исключение (владелец 19.11.2026) — только PNG-значки приложения в `pwa/` (раздел «Установка»). Ассеты из `node_modules` попадают в `dist/assets/<имя>.<md5>.<расш>` плоско (плагин `scripts/metro-asset-paths.js`: `.gitignore` batr-world режет каталоги `node_modules/`, `dist/`, `data/`…).
- **Никаких внешних запросов**: шрифты, данные, библиотеки — только в бандле. YouTube не встраивается: урок учителя открывается ссылкой во внешнем приложении (раздел «Материалы урока»). CSP в dist/index.html запрещает остальное. Без аналитики, трекеров, рекламы, Sentry, входа. Запросы — только на свой адрес: `POST /api/speech/v1/proverka` по нажатию «Проверить» (только свой домен) и, когда автор разрешит, файлы `media/…` (видео и клипы кари) по нажатию ▶.
- Новая зависимость — только по необходимости, `npx expo install`, затем `npm run licenses`. Свои файлы не из npm (подмножество Inter) — в `ЛОКАЛЬНЫЕ_ФАЙЛЫ` генератора лицензий и в `licenses/fonts/`.
- Плашка «Прототип. Черновик урока — проходит проверку устаза» — на каждом экране урока.
- Дизайн: только дизайн-система (раздел выше, `docs/дизайн/03-дизайн-система.md`); спокойно, без музыки, без лиц, без маскота, без жизней/сундуков/случайных наград/рейтингов/хасанат-счётчиков. Телефон 360–430 px и десктоп (колонка ~480 px).
- Тяжёлые данные (длинные тексты) — через `import()`: Metro выносит их в отдельный чанк с хэшем (пример — экран «Лицензии»).
- Минификатор пишет не-ASCII как UTF-8, а не `\uXXXX` (`metro.config.js`, `ascii_only: false`): JS сборки 875 КБ вместо 1415 КБ. Кодировка чанков — по `<meta charset="utf-8">` страницы (в первых 1024 байтах `public/index.html` — описание шаблона стоит ПОСЛЕ неё; проверяет check-dist). В комментариях шаблона не писать метки `%LANG_ISO_CODE%`/`%WEB_TITLE%`: Expo заменяет только первое вхождение.
- До загрузки JS в `#root` стоит строка «AI Ustaz загружается… / жүктелуде…» (react-native-web заменяет её при монтировании).
- Текст интерфейса со вставками арабского (названия уроков, вопросы, теория, пояснения) — через `СмешанныйТекст` (`components/info/MixedText.tsx`): арабские куски — Amiri Quran и изоляция направления (`ا/ء` не переворачивается).
- `docs/`, `CLAUDE.md`, `README.md` не трогать без задания. Не коммитить и не пушить — это делает ведущий.
